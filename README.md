# TemplaTD · 图形即防事

工坊里拼图形、提交进化成单格炮塔、送进一座独立的无尽塔防；花园里种图形生息，
库里抽卡扩编——三种资源各管一摊。无构建、无运行时依赖。

**首屏是「图形工坊」**。而这一版真正的新东西在战场上：**你摆下来的那些塔，
本身就是一具图形**。同一个 essence 把工坊图纸、花园全园、本局阵型放在同一把尺子上量，
所以「我这阵摆成了什么形状」第一次有了数字——而且那六个数字**各自接管一个战斗标量**。

上一版干这件事的是一张 24 条流、8 个奇点、无周期重连的代谢网，名词极繁到读不完，
玩家能积累的只有「上次那个叫什么来着，好像特别凶」。**它已经删掉了。**
现在接管战斗参数的是一个你看得见、改得动、读得懂的东西：你自己的摆位。
名词让位给读数——这就是**读数即裁判**，而不是**名词即裁判**。

## 跑起来

直接双击 `index.html`（或任意静态服务器打开）。

```bash
npm test          # 三道门禁：内核 → 界面 → 真实点击
npm run test:core # 只跑内核
npm run test:ui   # 只跑全部界面的挂载
npm run test:play # 只跑真实点击门禁（最重要的一道）
npm run test:balance # 平衡实测：一个普通玩家跑若干生涯（不进 npm test）
```

真实浏览器行为验证（不在门禁里，手动跑；需要本机 Edge）：

```bash
node tools/headless_check.mjs   # 真 Edge + CDP：导航顺序 / 悬停溯源 / 时钟 / 全页 / 截图
```

## 四本账

资源名在界面上**一律用全称，不缩成单字**——「采集尘 / 结晶 / 辉光 / 阅历」，
单字只许出现在内部字段与代码注释里。

| 资源 | 管什么 | 来 | 去 |
|---|---|---|---|
| **采集尘** | 原件获取 | 战斗结算按波数 · **花园的尘晶掉落加成** · 成就 | 抽卡 |
| **结晶** | 数值成长 | 战斗结算按波数 · 撑过第 10 波犒赏 · 成就 | 升级商店（**14 条线 · 四组**，含「阵型」组）· **装配台的模块** |
| **辉光** | 战斗 | 击杀掉落（随波缩放） | **战斗中随时升级塔** / 撤收退辉光（局内生局内死） |
| **阅历** | 可能性成长 | **战斗结算按战绩登记**（波数 / 深水 / 击杀 / 撤离） | 重塑树（**20 个节点 · 四分支**） |

> **结晶买数值，阅历登记可能性**。两本账的分工是这一版的根本决策：
> 结晶那条线回答「我要把哪条曲线抬高」，阅历那棵树回答
> 「我这一局还能做哪些以前做不了的事」。混了闸门，
> 「这一局打成了什么样」就没法与「下次我能做什么」对上号。

> 指针宇宙那一行已经删掉。它不新增闸门、不吃资源，只改战斗参数——
> 那一头现在由「阵型」接上（见下）。

## 核心循环

```
库（库存）        商店（抽取）      图形工坊          军械库          装配台          塔防（无限波）   花园
────────          ──────────       ─────────        ───────        ───────        ────────────    ──────
手里还剩什么  ←   采集尘换随机元件  拼图形(空格)  →   提交进化塌缩 →  装模块/拆解还料 → 部署在路径两旁   种图形备战
三道筛选          结晶买 14 条旋钮  六项读数试算     一座塔占一格    三块各认一种敌人  弹道/范围/优先  战斗掉落+增益
丢弃腾地方        概率当场公示      提交即消耗        TC-### + 流水   花结晶·一次性     撤收搬家        园子会长大
                                                                                      │
                                                                            一局结束 → 阅历登记
                                                                                      ↓
                                                                          重塑（第七页：成长树 + 重整）
```

**一局里的三处选择**：开局勾**战况**（这一局挨多少）→ 摆位（阵型接管标量）
→ 每波结束选**战备指令**（三选一，每条都有得有付）→ 撤还是顶（两笔不同的账）。

**阵型在这一版的地位**：战场上的塔 → 拓成一具 body → essence 原套六读数 →
六个标量（伤害 / 攻速 / 射程+穿透 / 散射 / 连锁+减速 / 暴击）。
补塔、撤收、拆塔都会让它换一张脸；波次推进不会——**乱流跟着部署走，不跟着波走**。
峰值那一项是双刃：它既是你的强项，也是这一局敌人的厚度（`hpMul`）。
所以「我这阵太偏环络了」是一句有代价的话，而代价写在同一个面板上。

**装配台在军械库旁边**：进化出来的塔先在这里上装备——三块模块各认一种敌人
（破盾尖锋打重甲与首领、裂界散射打灵体群、迅捷节律打冲刺兵），
每块吃一项读数，所以同一块模块装在不同图形上效果不同。
**请不起的塔也可以在这里拆掉**：元件回库，拼一具小的再来。

## 升级商店：四条成长轴

结晶的门口挂着四组旋钮（14 条线），分组不是装饰——它回答「我现在想改什么」：

| 组 | 管什么 | 线 |
|---|---|---|
| **开局** | 一局怎么开始 | 部署预算 · 起手拨付 · 容机预算 · 图纸扩容 |
| **循环** | 资源怎么滚 | 采集尘收取 · 抽取议价 · 高档权重 · 辉光精炼 · 结晶开采 |
| **手感** | 塔怎么打 | 膛压校准 · 循环加速 · 校射镜组 |
| **阵型** | **你自己摆出来的那个形状有多响** | 阵型增益（六项读数接管标量的幅度 +20%）· 峰值豁免（峰值抬高的敌血 −20%） |

**「阵型」组接替了上一版的「宇宙」组**。它不改塔、不改资源，改的是那六个读数本身。
两条旋钮各改一个真实存在的常数，买完当场生效——所以「我买的这条到底动了什么」
是一个能指着战场面板回答的问题。

## 运营：一局里真正在做决定的三处

旧版的休整期只有一个二选一（下一波 / 撤离），于是「运营」在一整局里只发生过
**一次**。而且失守与撤离的结算**逐字相同**——最优解因此是「永远点下一波直到死」，
撤离按钮是一个假决策。现在这三处各自成了一个问题：

### 1. 战况（开局前自己勾，参照《几何竞技场 2》的挑战卡）

**难度不是一档一档选的，是一张一张勾的**。九条加压项，每条右边写着它值多少
结算倍率（厚甲 +18% · 蜂拥 +25% · 渗血 +30%…），勾一条涨一点，倍率当场写在条上。
倍率同时乘在采集尘 / 结晶 / 阅历三样上——**风险与回报在同一行字里**。

分三档，起手只有三条；重塑树的「契约 I / II」各解锁三条。**局外成长抬的是
「你能赌多大」，不是直接给你数值**。

### 2. 战备指令（每波结束三选一，参照集成战略的节点分支）

每打完一波，桌上摊开三张（重塑可加到四张）指令，选一张——
**每一张都有得有付**，没有白给的选项：

| 指令 | 得 | 付 |
|---|---|---|
| 加固 | 基地生命 +2 | 下一波敌血 ×1.10 |
| 征募 | 辉光 +45（每波再 +9） | 下一波敌数 ×1.30 |
| 校准 | 下一波塔伤害 ×1.20 | 下一波辉光 ×0.75 |
| 侦察 | 看见后面两波 · +20 辉光 | 下一波敌速 ×1.12 |
| 潜伏 | 下一波敌速 ×0.82 | 下一波辉光 ×0.85 |
| 精简 | 撤收回扣提到八成 | 下一波敌血 ×1.08 |

只有得没有付，三选一就退化成「挑最大的那个」；有了付，你选的才是
**这一局往哪边长**。候选走**种子派生**，同局同波永远同样的三张。

**一条波一条令（2026-10-18 修订）：** 一波只许下一次令——三张卡都摊在桌上，
但 `now()` 是**立即**兑现的（加辉光 / 加基地生命 / 加容机），没有这道闸门的话
「三张全点」就是白拿三份。而**同一条指令可以在后面的波里再下一次**：
旧版按局去重（「这一条本局已经下过了」）拦错了地方——它拦掉的正是这一部
想要的重复决策：同样的取舍，在换过的局面下再答一遍。

### 3. 撤离 vs 失守：两笔不同的账

| | 波数收益 | 基地剩余 | 犒赏 | 阅历 |
|---|---|---|---|---|
| **撤离** | 全额 | 每点折算 3 采集尘 | 撑过第 10 波 +15 结晶 | 全额 |
| **失守** | **六成**（重塑「抚恤」抬到七成五） | 无 | 无 | **一半** |

这是**贪吃蛇的那一口**：多撑一波多一段收益，撑不住就把已经攒下的赔进去一部分。
深水区递增是它的另一半——第 10 波之后每波的收益都在变重（重塑「深水」抬斜率），
所以「继续」的诱惑是真的。两条一起，撤与不撤才都有话说。
（递增与难度倍率的思路参照《几何竞技场 2》：越深越值钱，而不是线性每波 +6。）

## 重塑：局外成长与重整（第七页）

一局打完 → 阅历入账（**逐条列出来源**：波数 / 深水 / 击杀 / 撤离 / 战况倍率 / 失守）
→ 去重塑页登记。二十个节点分四分支，**单前置**：

| 分支 | 管什么 | 例 |
|---|---|---|
| **启程** | 一局怎么开始 | 起手辉光 +80 · 加厚基座 +2 · 出厂校准（塔自带 1 级） |
| **战备** | 波与波之间能选什么 | 候选 3→4 张 · 每局一次重掷 · 高级指令 · 契约 I / II |
| **补给** | 局内资源怎么滚 | 辉光 +12% · 撤收回扣七成 · 升级 −12% · 护壁（漏怪 −1） |
| **结算** | 一局打完落袋多少 | 尘 +15% · 晶 +15% · 阅历 +20% · 抚恤 · 重整配给 · 深水 |

**横向解锁优先于纵向数值**——这是《明日方舟》集成战略「认知塑造」真正值钱的
那一半：它给的不是 +10%，是「下次可以这样打」。

**重整**也在这一页，而它是**常驻**的：

- **困住不由机器判定**。早期版本让 `stuck()` 去认那一个死结形状（没件 + 没塔 +
  尘不够抽一发），那是机器替玩家下判断——它能认的形状只有一个，而玩家不想再打
  下去的局面有一百种。现在这一键**随时可以按**，什么时候重来由人决定。
- **按下即结算这一局**。进行中的那一局按它现在走到第几波入账，再清局面：
  在波与波之间按 = **撤离**口径（全额 + 基地折算 + 阅历全额）；
  在交战中按 = **失守**口径（六成 + 无折算 + 阅历减半）。
  打了一半按重置不再等于白打，而「打到一半按」也占不到守完波的便宜。
- **只清局面**（库存 / 军械库 / 图纸 / 花园 / 这一局 / 两样资源），
  **履历留下**（阅历、重塑登记、成就、升级线、提交流水），
  并按已登记的节点数发配给（尘 80 + 30×n，晶 40 + 12×n）——配给是**保底**
  不是叠加：这一局落袋的比它多就留多的，少就把你抬到配给线。**二次确认**。
- 设置页那个改名「**彻底重置**」——那是真清零，两种必须一眼分得开。

## 敌人：十种，与波次的主题

**没有一种敌人是「什么都吃」的**——这是塔的属性分工成立的前提。
前五种管**属性**，后五种管**时间与地点**：

| 敌人 | 入场 | 逼你什么 |
|---|---|---|
| 步行兵 STRIDER | 1 | 什么都不逼——它是给你校准手感的 |
| 冲刺兵 DASHER | 3 | 攻速与减速 |
| 群兵 SWARMLING | 9 | 单只没血，成群才成立：单体火力会被淹掉 |
| 重甲 PLATED | 5 | 单体伤害只剩六成：连锁 / 穿透 / 溅射 |
| 疾甲 LANCER | 12 | 又硬又快：减速拖不住，单体也啃不动 |
| 裂胞 SPLITTER | 14 | 死时炸出两只群兵——**别让它死在基地边上** |
| 愈使 MENDER | 15 | 每秒回 7 点：小刀子割不动，要么一发打穿要么别碰 |
| 灵体 WRAITH | 7 | 单体只剩五成但血薄：溅射 |
| 壁垒 BULWARK | 16 | 单体只剩三成还带厚盾：这一局必须留一路非单体火力 |
| 首领 WARDEN | 10 | 每波的收尾 |

第 8 波起护盾入场，第 11 波起**每波有一个主题**（潮 / 疾 / 甲 / 灵 / 攻，五波一轮），
主题那一路抬五成并写在波次预告里。旧版第 11 波与第 12 波只是数字不同、问法完全一样，
预告也就没有看的必要；现在「下一波是甲潮还是灵潮」读得出来，才谈得上为它留火力。
新种类进来之后**常驻**——不是一次性演出，是往后的每一波都得算上它。

## 两种语言

界面支持**中文 / English**，在设置页切换（偏好写进存档，下次打开还是那个语言）。

- **中文是源**：界面里写的是 `T('战斗')`，那个中文串本身就是键。所以语言层可以整个拆掉
  或整个换上，十二页的调用点一个都不用动。
- **表项自带 `en`**：稀有度 / 型 / 特质 / 敌人 / 升级 / 成就 / 六种形变
  的名字是**造型语言的一部分**，翻译只写一次（`I.term(row)` 按当前语言取）。
- **门禁两条**：① 覆盖——把源码里所有会走 `T()` 的串抽出来（**看得懂跨行拼接**），
  逐条查词典，缺一条就红；② 逐页扫描——英文模式下把十二页的正文拼起来找汉字，
  有一处残留就红。加了新界面忘了上语言，一定会被其中一条挡住。
**阵型把三处接成了一个闭环**：工坊图纸的六读数决定塔强不强，花园的六读数决定
局外加成，而**战场上摆出来的形状**决定这一局的乱流偏哪一边。
三处用的是同一把尺子、同一套算法，一处算、三处看。

- **初始图形 3 枚**（升级与花园「轮廓」加成一路抬上去），
  元件只能抽，目录已删——同一序号可攒多枚。
- **工坊图纸 14×9 起步**，升级商店的「图纸扩容」（4 级）让长宽各 +2，
  满级 22×17；只扩不缩，已放下的元件永不搬家。
- **局中也能放塔**：部署阶段走预算、可撤回；开战之后走本局辉光、不可撤回。
  挑选条在三个相位都摆着——「打着打着发现这儿该补一座」是塔防最基本的乐趣。
- **塔的属性随图案大幅波动**：六项读数的系数按实测分布标定，
  同一片元件摆法不同，伤害能在 5.7–13.1 之间走、连锁能从 0 抬到 7。
- **不同炮对应不同图形**：十八种型各带一份**战斗签名**（`sig`），
  直接加成到属性上。同一具图形换主料，进化出来就是另一种塔——
  型名因此成了战术语言，而不只是标签。
- **战场 22×14**（旧版 16×10，格子 20px → 24px）：面积接近翻倍，格子也更好点。
  摆位太挤的话「谁挨着谁」这门学问还没展开就用完了——邻接回路要有一条路上
  并排坐下三四座塔才有的可算。代价：难度墙往后挪了一格（`_balance.mjs` 量过）。
- **战场上看不到字**：塔画它自己的形状（按稀有度着色），十种敌人各有自己的形状——
  边数即读数（越难缠的边越多），三种不靠边数：群兵是最小的那个圆、
  裂胞是两个圆（正在分成两只）、愈使是个十字（它在补自己）。
- **十种敌人，每一种各管一种塔的短板**（详见下节）。除了属性分工，
  后五种问的是**时间与地点**：裂胞逼你决定「别让它死在基地边上」，
  愈使逼你用爆发而不是小刀子割，壁垒逼你留一路非单体火力。
- **第 8 波起敌人带盾**：重甲 / 疾甲 / 壁垒 / 首领的护盾先吃伤害，
  **单体（直击 / 近战）打盾只有五成**，溅射 / 连锁 / 穿透 / 灼烧全额。
  所以「伤害够高」不再够用——得留一路非单体火力。
  盾量随波数缩放（与敌血同一根轴），波次预告与战场上都有那圈青色虚线环。
- **塔防是无限模式**：第 11 波起骨架加码，HP/速度/报酬全程缩放；
  休整期二选一——下一波继续顶，或撤离落袋。
  **升级在战斗中就能点**（点塔 → 升级）：辉光是击杀里挣的，局内挣的就该局内花得掉。
  **塔的详情在波次中随时能开**：点战场上那座塔，或点战斗页顶上「塔条」的一行
  （每座塔一行，图形 + 编号 + 等级）——不必在 22×14 的棋盘上去找那一格。
- **局中能撤收**：开战之后把一座塔摘下来，返六成辉光、塔回军械库——
  「这儿摆错了，认了还是花四成搬个家」从此是个选择。重新部署要再付全价。
- **花园**：**16×12 起步、没有设计上限**的常驻板。每满 16 格，长宽各 +2 向外扩一圈，
  **只扩不缩**——挖走元件也不会把园子缩回去，已种下的东西永远在新界内。
  花园的功能是**战斗辅助**：**每一件**按自己的六项读数给两类加成——
  **战斗掉落**（辉光 +% / 尘晶 +%）与**增益**（伤害 / 攻速 / 射程 / 暴击）。
  它不再是挂在墙上时钟上的被动水龙头，而是「我为下一局准备了什么」。
  **苗床**：最早种下的 96 格，出力额外再给一半——挖走早年的件，后面的件会顶进苗床。
  离了根的件（挖断留下的孤件）出力折半，所以「贴着根种」不只是放置约束。
- **测量页**照搬 CONFIGURA：六项各有「怎么验」与判据明细，全部真算。
- 成就九条，只盯图形数据与部署事实，达成即入账。

## 六个别改回去的地方

1. **每页独立容器**：`app.go()` 新建容器、离场 `unmount()`、时钟只驱动当前页。
2. **门禁必须包含 `smoke_play.mjs`**：只派发真实 DOM 事件；绿了的测试和能玩是两件事。
3. **塔防不认识图形**：`core/td.js` 只吃属性块与**纯数据乱流**，禁 import parts/tower/shop/essence。
   乱流（`opts.flux`）与 `{spec, at, pri}` 是同一种东西——一张已经算好的标量表。
   `run.js` 是唯一同时知道两边存在的地方，转交只发生在那一层。
   `BS.apex` 仍留在禁用清单里：那一页删了，但**不许回来**。
4. **战斗中不许整页重画**：`world/mods/battle.js` 分两层——**结构指纹**（相位 /
   选中 / 塔数 / 等级 / 形变 / 暂停 / 倍速）变了才重搭骨架并重新绑事件，
   指纹没变就只补数字与格子（**目标优先级不在其中**，见 37）。旧写法每 160ms 把 `host.innerHTML` 整个换掉，
   于是 mousedown 与 mouseup 落在不同节点上，浏览器根本不出 click——
   **真人点击十个里丢九个**，而 jsdom 的同步派发让门禁一直是绿的。
   判据只有一条但必须是真的：跑过时钟之后，那个按钮还是同一个节点。
5. **悬停绝不重渲染**：ghost/试算只改 class、只写固定盒子。在 mouseenter 里 render()
   会让真实浏览器里 click 落不到格子上——「无法部署」翻过一次车。
6. **四本账各管各的闸门**：采集尘只管抽、结晶只买数值旋钮、辉光只管局内、
   阅历只登记重塑树。混了闸门，「随局势成长」的节拍就散了。
   阵型乱流与战况**不新增闸门**——但它们**改战斗参数**：
   六项读数各接管一组标量（`dmg/rate/range+pierce/proj/chain+slow/crit`），
   再加两项与塔数挂钩（漏怪减免 / 辉光产出）和一项反噬（峰值 → 敌血）。
   闸门不变，扰动是真的，而且**每一个数字都指着它的来源**。

## 另外几条同样别改回去

7. **`armory` 与 `armoryLog` 是两回事**：前者是「现在还在库里」，淘汰与开战
   都会删它；后者是「提交进化的流水」，**只增不减**。删掉任一条路径的写入，
   「我做过一座什么样的塔」就会随淘汰或开战一起蒸发。两条删除路径都要记住：
   淘汰（`shop.discard`）与消耗（`run.consumeDeployed`）。
   写流水时是**独立副本**（`shop.recSnap`），历史不许被在库记录改写。
8. **导航编号按数值排**：`registry.list()` 不能再退回 `localeCompare`——
   字符串比较会把 `'10'` 排到 `'2'` 前面，军械库从 9 提到 10 之后就会莫名跳位。
9. **商店与库是两页**：抽卡 + 升级在商店页，库存列表在库页。
   库页不许再出现抽取/购买按钮——半拆状态最难查，门禁里有一条专门钉这个。
10. **开局之后也要能放塔**：`run.add()` 曾经整个锁在 `phase === 'deploy'` 里，
   于是开战之后库存里的塔再也摆不下去。现在三个相位都能放，
   区别只在钱从哪儿出（预算 vs 本局辉光）与能不能撤回。
   改回去就等于把塔防最基础的乐趣关掉。
11. **提升曲线一律走小于 1 的幂次**（`eff.pow(x, k) = k·x^0.6`）：
    升级效果、塔等级、花园加成三处都从这一个口子出。
    一级的数字与线性版逐字相同，但第四级不再是四倍——递减而不封顶，
    「先升哪一条」才重新成为决策。成本仍然线性：收益递减、成本不递减，
    晚买的级别才真的更不值。
12. **花园加成是参数进来的，不是查出来的**：`td.js` 不引用花园（门禁扫源码）。
    算那张纸的是 `run.js`——它是唯一同时认识两边的地方，与乱流同一套规矩。
13. **专精在装配台，不在战场上**：模块是**局外花结晶**装的（`shop.fit`），
    一次性；效果在 `run.specsOf` / `run.add` 折成这一局的属性块，落地只有
    `TD.applyBranch` 一个**纯函数**（输入那块不动——它是在库记录拿着的那份）。
    别把入口挪回休整期的辉光升级：塔开战即消耗，模块跟的是这座塔的这一次出征，
    「出发前想清楚这一局怎么打」才是它制造的决策。
14. **护盾只有一条规则**：盾先吃；单体（直击 / 近战）五成，其余全额。
    别再在 `hurt` 之外夹第二道——散落的 clamp 是漏抽象的老巢。
15. **拆解还料不许省**：淘汰把这座塔的元件还回库。这不是慈善，是**死结的钥匙**——
    一具贵过全局部署预算的塔若不能拆，玩家会被锁死在局外（尘只能靠战斗结算挣）。
    `_balance.mjs` 的死结体检抓过这个局，它是这条规则的看守。
16. **撤收返六成，不是全额**：全额退款会让「先随便摆上去试试」零成本，
    摆位就不再是决策。过路费就是这条线的意义。
17. **模块的浮动部分吃读数**：每块模块的 `fx(a, es)` 从 `spec.es` 取一项读数。
    写成常量的话，「同一块模块装在不同图形上效果不同」当场塌成一句注释。
18. **手上那件是借出来的**：在工坊/花园「拿在手上」= 从库 `takeOne` 出去的那一枚，
    所以页面走人时必须 `dropHand()` 还库——`mount` 里直接写 `hand = -1` 就是
    **切页吞件**（用户报过这个 bug，工坊与花园同源，两个都要还）。
19. **升级不锁相位**：`run.up()` 只挡 `deploy`（钱是预算不是辉光）与 `over`；
    按钮在 `battle` 与 `rest` 都摆着。辉光在击杀里挣，就跟着战斗花——
    锁成「只有波与波之间能升」等于把局中打出来的钱锁死在账上。
20. **存档与重置只有一个家**（设置页）：顶栏不放存档钮，图鉴页不放清空钮。
    重置必须**二次确认**（先亮确认、再动手），而且导出/导入要给它一条回程——
    没有回程的重置是事故，不是功能。
23. **质变口是两口，不是三口；但一个口上可以叠**：六项读数 → 六种形变，
    一座塔一辈子各选一次（焊死）。三口的话第三口必然空着，而空着的那口会
    **静默退化成普通升级**——那是这一部最讨厌的形状。
    **叠加是本版加的**：形变互不替换、各管一条规则（过载管节拍、穿模管盾、
    寄生管连锁衰减……），所以「再来一条」不会挤掉上一条。`t.gate` 记着
    「这一口开在哪一级」，一个口上叠几条，等级都只 +1——**叠的是规则，不是级数**。
    质变口**不收辉光**：辉光买的是「更痛」，规则不该挂价签。
    出口必须摆在同一块面板上（开口之后「升级」钮照常显示）——
    否则叠到一半想收手的人会被锁在口上，那比原设计更糟。
24. **形变必须改规则，不是改数字**：`TD.mutate()` 拷一份属性块、往 `mut` 里记一个 id，
    真正做事的是 `tickOnce` / `hurt` 里那几个 `mutOn(t.a, …)`。
    写成「伤害 +30%」的话，它就只是第 10 级——而玩家早就有一堆 +30% 了。
25. **摆位不许反向写进属性块**：阵型读数只进乱流（`opts.flux`）与塔实例上的 `wire`，
    绝不碰在库那份 `spec`。把审美变成数值外挂，「读数即裁判」当场塌成一句注释。
    门禁里有一条专门钉这个（同一批塔换摆法，属性块逐字节相同）。
26. **撤离与失守必须是两笔账**：失守打折（六成）、阅历记一半、没有犒赏。
    两笔账一样的话，「永远点下一波直到死」就是唯一解，撤离按钮是假的。
    门禁里有一条专门钉这个（同一副部署跑两遍，失守的尘与阅历都必须更少）。
27. **战况与指令只走一张 mods 纸**：它们是**纯数据块**，与乱流、花园加成
    同一种东西，由 `run.modsOf()` 算好交给 `TD.setMods`。塔防不认识战况、
    不认识指令——散落在战斗里的第二处判断，是漏抽象的老巢。
28. **指令的账跟着波走**：进休整期必须清掉 `ordMods`（`run.toRest()` 是唯一入口）。
    界面那条路（时钟推到波末）与 `step()` 那条路都得走它——漏一条，
    「上一波的加固」会一直压在场上。
29. **每条指令都要写「付」**：只有得没有付的三选一退化成挑最大的那个。
    门禁里有一条逐条查 `pay` 字段。
30. **重整只清局面**：库存 / 军械库 / 图纸 / 花园 / 这一局 / 两样资源归零；
    阅历、重塑登记、成就、升级线、**提交流水**一笔不动。它是玩法的一部分，
    所以长在重塑页；设置页那个叫「彻底重置」，两种必须一眼分得开。
31. **困住不由机器判定**。早期版本的 `stuck()` 只认一个形状（没件 + 没塔 +
    尘不够抽一发），那是机器替玩家决定「你现在该重来了」——它能认的形状只有一个，
    而玩家不想再打下去的局面有一百种。现在重整那一键**常驻**，什么时候按由人定；
    界面只写代价，不写判词。门禁里钉了一条：`BS.meta.stuck` 必须不存在。
32. **按下重整即结算这一局**：进行中的那一局按它走到第几波入账——休整期按撤离
    口径、交战中按失守口径。旧版直接丢弃，打了一半按重置等于白打；
    而「交战中按」也不许比守到休整期更划算，否则它就成了躲掉失守的捷径。
33. **配给是保底不是叠加**：`rally()` 发下的尘 / 晶取 `max(现有, 配给)`。
    叠加的话「打一局、按重置」就是一台抽水机。
34. **新敌人只加纯数据字段**：`regen`（每秒回血）与 `split: {id, n}`
    （死亡分裂）写在敌人表上，`td.js` 里没有一句「如果敌人是裂胞那么」。
    出生与**分裂**共用同一个 `spawnAt()`——分开写两遍的代价是
    「分裂出来的不缩放血量」，而这种 bug 只在第 20 波之后露面。
35. **撤一页不等于撤一份履历**：卷宗删掉之后，`meta.history` 那一条数据
    没有跟着页面消失——它搬进了图鉴（垫底的最后一页，兼收战绩与最近记录）。
    页面是投影，数据是账本：账本不许因为没有投影就清零。
    图鉴因此从「参考书」变成「档案 + 宪法」，而它垫底是故意的——
    参考与档案不该挤在工坊与战场之间。
36. **数组里的界面串过不了覆盖门禁**：图鉴那张「四本账」表把四行装在数组里
    喂给 `T(rows[i][2])`，而覆盖门禁的抽取器只认 `T('字面量')`——
    它看不见数组里的串。守那几行译文的是**逐页汉字扫描**（界面门禁），
    不是覆盖检查。往数组里加界面串时两条门禁都要过，别只跑第一道。
37. **优先级不进结构指纹，等级也不碰优先级**：目标优先级是**选择态**，不是结构——
    它一变就由 `patch()` 当场补那三个钮的高亮（`skel.pri`），绝不重搭骨架：
    重搭会把钮销毁重建，而它在一场战斗里会被来回点十几次。
    旧版把它漏在指纹之外、`patch()` 又不管它，于是高亮只在**等级变了**
    （唯一进指纹的塔字段）时才对——玩家读到的是「升级把优先级改掉了」，
    而塔的判定其实早就变了。现在两件事各走各的路：等级变了重搭骨架，
    优先级变了只换几个 class。
38. **塔详情的两个入口，且点塔先于放塔**：点战场上的塔，或点战斗页的「塔条」。
    点击判定里**塔格那一支必须排在放塔之前**——旧写法先走 `sel >= 0` 的放塔分支，
    于是武装着一座待放的塔时，点塔格只换来一句「这一格已经有东西了」，
    详情面板在整个武装期间打不开。`deploy` 不摆塔条（塔动不了，点开只是噪音），
    `rest` 用完整的塔列表。

## 资源全称

界面上**一律「采集尘 / 结晶 / 辉光 / 阅历」**，不缩成单字。内部字段名（`dust`/`crystal`/`lux`/`exp`）
与代码注释里的简称不受此限——被禁的是**给玩家看的字**。
门禁里有一条直接扫顶栏 HTML，防的是「某个新页又随手写了个 `H.kv('尘', …)`」。

## 读数即裁判：阵型怎么接管战斗参数

- **乱流跟着部署走，不跟着波走**。上一版每波重掷一次接线，玩家能积累的只有
  「上次那个叫什么来着，好像特别凶」。现在它只在一件事上换脸：部署变了
  （补塔 / 撤收 / 拆塔）。所以「这一波偏什么」是个稳定的观察，不是每波换一次的雪花。
- **六项读数各接管一组标量**（`run.js` 的 `FMAP`）：
  匀质→伤害 · 重复→攻速 · 通透→射程与穿透 · 对称→散射 ·
  环络→连锁与减速 · 轮廓→暴击。另有漏怪减免与辉光产出跟着塔数走。
- **峰值是双刃**：六项里最高的那一项，同时把这一局的敌血抬高一格（`hpMul`）。
  所以「偏科」是有代价的，而代价写在同一个面板上——读得懂，才叫决策。
- **可复现一个字都没破**：阵型是部署的纯函数，同种子同部署逐 tick 一致。
  没有钟、没有自由活动的相位，所以也不再需要什么「定版叉」。
- **接缝（邻接回路）**：相邻两座塔按各自峰值算一个关系——
  共振（同峰值、都不太响）互相抬一手；干涉（同峰值、都太响）伤害打折换射程；
  互补（峰值不同、都够响）各读到对方整个峰值。
  于是**排列顺序**第一次有意义：摆位从「覆盖哪些格」变成「谁挨着谁」。

## 单语

这一版是**单语作品**：拆掉了 en/ja/ru 三套词典、扫描器与覆盖门禁。
`core/i18n.js` 现在只做一件事——让 `T('战斗')` 这个调用点在全部十二页里原样跑通，
直通中文。拆语言没有动过任何一页的调用点，这就是把语言收在一层的价值。
