# TemplaTD 设计文档 · 图形即防事

> 这一份是重构的宪法。每一条机制都写清它**制造了哪一个新决策**——造不出新决策的系统，不进这一版。
> 架构基准：`personal` 的构造协议（声明式表驱动、单点收敛 `eff()`、种子化可复现、子界面自治走总线、注释只写为什么）。
> 体量不设上限，但单文件仍守住 ≤500 行；逻辑与数据分居 `core/` 与 `world/`。

---

## 0. 一句话定义

**TemplaTD 是两个系统、一座桥、一座花园、一道质变口、一张接缝网。** 图形工坊（系统 A）把整块正方形的
元件拼成图形，提交后**进化**成只占一格的炮塔；塔防（系统 B）是难度不断上升的
**无限模式**，只认属性块——第 8 波起敌人带盾，逼玩家为非单体火力留位置。
花园让种下的图形生息——三种资源各管一摊：
采集尘管抽卡、结晶管成长、辉光管战斗。**装配台**是出发前的那一站：
进化体在这里装模块（三块各认一种敌人、每块吃一项读数），请不起的塔也在这里拆回元件。

**这一版删掉了「指针宇宙」**（系统 C，24 条流 / 8 奇点 / 无周期重连 / 7 刻度）。
它接管战斗参数的那一头没有跟着一起删——接上它的是**阵型**：
本局摆下来的那些塔，本身就是一具图形，用同一把 essence 量出六项读数，
各接管一个战斗标量。名词让位给读数：玩家能积累的不再是
「上次那个叫什么来着，好像特别凶」，而是「我这阵太偏环络了」。
另外新增两道：**质变口**（第 2 / 5 / 10 级各开一口，一口一条新规则，最多三口，
且不收辉光；2026-10-18 修订：旧版写在 3 / 6 / 9 且允许同口叠加，
而等级封顶是 9——第三口永远开不了，叠加又把「选一条」稀释成「选三条」，两处都改掉了）
与**邻接回路**（相邻两座塔按各自峰值算一个接缝）。
审美即战力，这是这一部作品唯一的主张。

## 0.1 阵型（本版的核心增量）

### 为什么它不是装饰

**玩家摆出来的形状，必须真的打到敌人身上。** 上一版的指针宇宙用二十四条流、
八奇点、无周期重连做到了「每一个数字都算得出来」，但它同时做到了另一件事：
玩家读不懂。于是它制造的不是决策，是印象。

阵型把同一件事换了一个来源：**你能看见、能改动、能指着说话的那一个**。

| 约束 | 落地方式 |
|---|---|
| **不许是估算** | 直接调 `essence` 的原套六项读数（`BS.body.stats`），与工坊图纸、花园全园同一把尺子，一格未改 |
| **不许无源之水** | 输入只有一件东西：本局已部署的塔的坐标。塔在哪儿，读数就从哪儿来 |
| **不许不可读** | 战场面板把「多少 → 接管什么 → 净效应」三件套并排摊开；峰值那一项单独点出它是双刃 |
| **不许反过来改属性** | 阵型只进 `opts.flux`（纯数据块）与塔实例上的 `wire`；在库那份 `spec` 一个字节都不碰 |

### 六项读数接管战斗参数（强耦合 · 读数即裁判）

`run.js` 的 `FMAP` 是那张唯一的对照表：

| 读数 | 接管的标量 | 系数 |
|---|---|---|
| 匀质 even | 伤害倍率 | 1 + 0.30·v |
| 重复 repeat | 攻速倍率 | 1 + 0.30·v |
| 通透 void | 射程加成 + 穿透 | 0.60·v ／ ⌊2·v⌋ |
| 对称 sym | 散射弹数 | ⌊2·v⌋ |
| 环络 weave | 连锁跳数 + 减速幅度 | ⌊2·v⌋ ／ 1 + 0.30·v |
| 轮廓 edge | 暴击概率 | 0.22·v |

另有两项跟塔数走（围得越厚漏怪越少、塔越多辉光产出越高），
**外加一项反噬**：六项里最高的那一项，同时把这一局的敌血抬高一格。

**峰值是双刃**——这是阵型与上一版乱流最本质的区别。上一版的扰动是零均值的：
好坏各半，玩家只能记趋势。现在偏科是有代价的，而代价写在同一个面板上：
「我这阵太偏环络了」是一句有数字可查的话。

### 边界不许破（README 规矩三）

`td.js` 仍然不认识图形、不认识 essence、不认识花园。它只吃一个已经算好的
`opts.flux` 块——算那张纸的是 `run.js`，它是唯一同时认识战场与 essence 的地方。
（门禁把 `BS.body` 与 `BS.essence` 一起钉在禁用清单里，就是为了这条。）

哪怕传进来一个畸形的块，战斗只会退化成「没有乱流」，绝不会崩——
每一项都在 `fluxOf()` 里钳死，使用点不再假设任何东西。

### 可复现：不再需要「定版叉」

上一版的乱流每波重掷，而重掷依赖一个自由走动的钟，所以必须 `freezeCombat()`
把相位归零才能保证「同种子同部署逐 tick 一致」。

阵型是**部署的纯函数**：塔在哪儿，读数就在哪儿。补塔、撤收、拆塔各重算一次，
波次推进不重算。没有钟、没有相位，所以那条定版叉整个不需要了——
可复现从「靠冻结达成」变成「靠定义达成」。

### 门禁

`test/smoke.mjs`：「阵型」一节（换摆法读数必须变、塔的属性块逐字节不变）+
「乱流」四节（中性 = 没有乱流 ／ 强弱打出不同战果 ／ 畸形不崩 ／ 同乱流同种子逐 tick 一致）+
「阵型组」一节（两条旋钮真的改到 formationFlux 的常数上）。

`test/smoke_play.mjs` 在真实 DOM 上验证**阵型浮层真的画出来**：
六项各占一格、每格都有「读数 / 净效应 / 接管标量」三件套、峰值被单独点出。


## 1. 三种资源（本版的根本决策）

**命名规则**：界面上**一律全称**（采集尘 / 结晶 / 辉光），单字只留在内部字段
（`dust`/`crystal`/`lux`）与代码注释里。三字名比单字长，但「采集尘」三个字本身
就说明了它是干什么的——这比省两个字的横向空间值。

| 资源 | 名 | 来 | 去 | rationale |
|---|---|---|---|---|
| 原件获取 | **采集尘** | 结算 6/波 ×加成 · 成就 | 抽卡（25 采集尘/发起） | 抽卡的门票只剩结算这一条水龙头（+ 成就的一次性奖励）。花园的**尘晶掉落**挂在结算那一个乘区里——种得好，抽得更快 |
| 局外成长 | **结晶** | 结算 2/波 ×加成 · 撑过 10 波犒赏 15 · 成就 | 升级商店十二条线 · **装配台模块（40/块）** | 成长的闸门唯一，升级全是全局旋钮（详见 §2.1） |
| 战斗 | **辉光** | 击杀掉落（随波缩放 ×1.06ⁿ） | **战斗中随时升级塔** · 撤收退辉光 | 局内生局内死——它不折算、不持久，战斗的成长留在战斗里 |

**三道闸门不许混**：采集尘不能买升级、结晶不能抽卡、辉光带不出局。
混了闸门，「随局势成长」的节拍就散了。**装配台走的是结晶这道闸门**——
模块是局外成长（出发前装好，跟这座塔打它的那一局）。

## 2. 库与商店：花出去的动作与手里的存货分家

**这一版把「库」拆成两页**，理由是一屏里两个问题互相抢注意力：

| 页 | 答的问题 | 内容 |
|---|---|---|
| **库**（2） | 我手里还剩什么？ | 库存列表（三道筛选、分页、丢弃） |
| **商店**（3） | 我能把资源换成什么？ | 抽卡（含**概率公示**）+ 升级商店十二条线 |

半拆状态最难查（拆了页但按钮还留在老地方），所以门禁里有一条直接钉：
库页不许出现 `draw:*` 或 `buy:*` 按钮。

### 2.1 抽卡概率公示

概率显示不是装饰。`core/store.js` 把 `rollRarity` 拆成两半：

- `weights()` —— 算五档最终权重（基础 × 成就/升级 rarBoost）；
- `odds()` —— 把权重归一到 0..1，并附一份**基础参照值**；
- `rollRarity()` —— 只负责拿 `weights()` 掷骰。

**显示与抽取读的是同一份 `weights()`**，所以那个百分比永远骗不了人。
商店页的每档都带基础参照：抬过档的会加 `moved` 高亮与 `+x%` 后缀，
玩家能看见自己买到了什么。另给一句「一百抽大约出 N 张华档以上」——
概率条负责精确，这一句负责直觉。

### 2.2 升级商店：十七条线，分四组

分组是给玩家一个「我现在想改什么」的入口，不是装饰：

| 组 | 管什么 | 线 |
|---|---|---|
| **开局** | 一局怎么开始 | 部署预算 · 起手拨付（新局白给 +80）· 容机预算（可部署上限 +2/级）· **图纸扩容（工坊板长宽各 +2/级，4 级封顶）** |
| **循环** | 资源怎么滚 | 采集尘收取 · 抽取议价 · 高档权重 · 辉光精炼 · 结晶开采 |
| **手感** | 塔怎么打 | 膛压校准（伤害 +8%/级）· 循环加速（攻速 +6%/级）· 校射镜组（射程 +0.4/级） |
| **阵型** | **你自己摆出来的那个形状有多响**（本版） | 阵型增益 · 峰值豁免（见 §2.4） |

**「图纸扩容」是一条不落进 `mods()` 的升级**，这点值得单独说明：它不改任何数值修正，
而是被 `core/shop.js` 的 `roomLv()` 直接读层数来算板子尺寸。
一条升级不必非得变成一个乘数——**只读层数也是一种合法接法**。
`mods()` 里故意不处理 `room`，并由门禁保证 `shop.roomLv()` 真的读到层数。

**关键实现细节**：`tower.attrs()` 有按图形签名的缓存，而「手感」三线是**全局**的。
若把升级乘进缓存，买完之后老塔还是旧数值（缓存命中，永不刷新）。
所以 `attrs()` 被切成两段——`base()` 走缓存（由图形决定），修正段**每次都算**
（由 meta 决定）。这样买完升级，全场塔当场生效，不需要手动失效任何缓存。
门禁里有一条专门钉这个：买前买后同 part 的 dmg/rate/range 必须递增。

### 2.3 提升曲线：一律小于 1 的幂次（本版）

**所有「叠加越多越强」的曲线都走 `eff.pow(x, k) = k · x^0.6`**（`core/eff.js`）。
为什么要它：线性叠加在长线游戏里必然逼出「全都升」这一个解——
第 10 级和第 1 级一样值钱，玩家就没有「先升哪一条」的决策了。
p < 1 让曲线**递减但不封顶**：每一级仍然变强，只是越往后越不值。

形状（以 `dmgMul` 为例，一级仍是 +8%）：

| 层数 | 旧（线性/复利） | 新（幂次 0.6） |
|---|---|---|
| 1 | ×1.0800 | ×1.0800 |
| 2 | ×1.1664 | ×1.1213 |
| 4 | ×1.3605 | ×1.1843 |
| 9（满级前） | ×1.9990 | ×1.2684 |

**改曲线不动一级的手感**——老玩家第一次买到的还是那个数，
只是买到第 4 级时不再有 4 倍。这是「改曲线」和「改平衡」的分界线，
门禁里有一条专门钉：一级必须与旧版逐字相同，四级必须明显低于复利。

三处从这一个口子出：

| 处 | 曲线 |
|---|---|
| 升级商店（12 条线） | `A · lv^0.6`（rar 线是 `1.5^(lv^0.6)`） |
| 塔等级（`td.levelMul`） | `1 + 0.25 · lv^0.6` |
| 花园加成（`garden.mods`） | `GAIN · (raw^0.6 + 苗床^0.6 × 0.5)`，raw = Σ_件(读数 × 格数/16 × 主副权) |

**成本不跟着改**：升级价格仍是线性（`40 + 40·l` 起）。
收益递减、成本不递减，晚买的级别才真的更不值——两头都递减，
升级就永远不亏，曲线白改。

> 实现上有一条：**层数一次折进幂次，不要逐级循环再逐级 concave**。
> 逐级折会把曲线折两次，数值会低到看不出成长。这条写在 `mods()` 的注释里。

### 2.4 「阵型」组：优化你自己的摆位（本版增量）

前十二线改的都是**这一局里看得见的东西**（预算、资源、塔）。第十三到十七条改的是
**上面那张网自己的常数**——它本来就是十二个战斗标量的来源，所以「把网调好」
与「把塔调强」是两条独立的成长轴。

| 旋钮 | 改哪个常数 | 为什么它是这条轴上的东西 |
|---|---|---|
| 接线收束 | `BIND_CAP` +0.03/级 | 单条流对战斗标量的影响上限。抬它 = 让**每一条**流更响（好坏一起） |
| 顺流校准 | 正向 ×(1+8%/级)、逆向 ×(1−6%/级) | 唯一一条**只往好处修**的：正偏放大、逆流收敛 |
| 流场增益 | `FLOW_DIV` −0.08/级 | 流值归一的饱和点。降它 = 同一条流读得更满 |
| 外源拓张 | `exogen().v` ×(1+10%/级) | 唯一入口「外源」本来只读进度，现在它也能被投资（但**仍然只有这一个入口**） |
| 泄压阀 | 通胀压力 ×(1−12%/级) | 正反馈（饱和→倒灌→环络）是这张网唯一危险的地方，降的是累积速度，硬顶照旧 |

三条实现口径，缺一条这个组就不成立：

1. **零级逐字等于旧值**（0.35 / 1.6 / 0 / 0 / 1）。门禁第一条就断言它——
   老存档买不起这些旋钮时，这张网与上一版**一模一样**。
2. **落地只在 `run.js` 的 `formationFlux()`**：`metaDefs.mods().formScale / formRelief`
   两个乘区各改一个真实存在的常数，
   其余模块不许再夹。与「单点收敛」同一条规矩。
3. **缓存带常数指纹**：`combat()` 的相位缓存同时对比 `waveSeed` 与 `kSig()`——
   买了旋钮而缓存不失效，「接线收束」会静默地等到下一波才生效（半生效状态）。

界面这一侧也不许含糊：战场阵型面板把**买到的常数**的效果当场报出来（零级时读数原样），
溯源面板里那条「接管 X」的净效应也用**当前常数**现算——它与战场吃到的数是同源的。

## 3. 图形工坊（系统 A）

- **14×9 组装板**（本版从 10×6 抬高），CONFIGURA 的手势：**放置只认空格、点击只认查看**、
  R 转手上件、Del 拆选中整件；库区三道筛选照库页模式。
  - 尺寸不是常量：`shop.cols()` / `shop.rows()` = 基准 + 升级层级 × 2，
    由升级商店的「图纸扩容」线（`room`，4 级封顶）逐级放宽 —— 满级 **22×17**。
  - **只扩不缩**：升级只会把上界变宽，已放下的元件永远落在新界内，
    不需要搬移、迁移或清理任何已有图纸（门禁断言旧格 key 与格数不变）。
  - **故意不导出 `COLS`/`ROWS` 常量别名**：留一个静态常量在那儿，
    迟早有人拿它当「当前板子尺寸」用，而那是错的。要尺寸就走 `cols()` / `rows()`。
  - 板子越大，能容纳的成分越多、对称与环络上得去，质变度（进而炮塔属性）越有空间——
    所以「扩容」是一条实打实的成长线，不是摆设。工坊页头部把
    「图纸 16 × 11 / 扩容层级 1 / 格数 176」直接摆出来，买完升级数字当场动。
- **试算**：悬停克隆图上放一件，试「质变度 a→b · 部署成本 a→b 辉光」——
  先知代替后悔。ghost 只碰 class，绝不重渲染（见 §9 翻车记录）。
- 提交进化：整具图形量六项（essence 原套算法，一格未改）→
  塌缩成 1×1 炮塔（TC-###）→ 进军械库，**同时写一条提交流水**。
  **提交消耗元件**，图纸清空。
- 成本 = ⌈2/格 × 格数 × 最高档稀有度 × (1 + 质变度 × .5) + 特质×8⌉。
- **库无上限**：元件爱攒多少攒多少（旧版的「库容 3→8」与「满库抽不动」已撤）。

### 3.1 军械库与提交流水（本版增量）

军械库现在有两栏，回答两个不同的问题：

| 栏 | 是什么 | 会不会少 |
|---|---|---|
| **在库** | 现在能部署的塔 | 会——淘汰删它，开战消耗也删它 |
| **提交流水** | 提交进化的底账 | **不会**——只增不减 |

为什么必须有两栏：「淘汰」与「开战消耗」都会删在库记录，删掉之后你就再也
说不出「我做过一座什么样的塔」。所以 `shop.submit()` 在提交那一刻同时写两份
（`armory` 与 `armoryLog`），流水存的是**独立副本**（`recSnap`）——
历史不许被在库记录改写，这一点有专门的门禁断言。

老存档没有 `armoryLog` 栏：`bus.norm()` 会拿在库列表补一份。注意判「缺栏」
要判在**原始存档对象**上，不能判在 `blank()` 出来的默认对象上——
后者已经有空数组，`Array.isArray` 永远为真，补偿分支一次都进不来。

### 3.2 装配台：模块装在出发之前（本版增量）

**为什么专精必须长在装配台，而不是战场上。** 第一版把它做在休整期
（花本局辉光、3 级起、二选一）——`_balance.mjs` 一量就露了两个洞：
① 塔开战即消耗，模块跟着这座塔打**它的那一局**，所以它天然属于出发前，
不属于局中；② 局中选分支等于「打一半再看」，而这一部要的决策是
「出发前想清楚这一局怎么打」。于是整条链改道：**局外花结晶装，一次性，
效果在开战时折成属性块**。

`world/mods/assembly.js` 是这一页（导航 11，排在军械库之后）：

| 块 | 效果 | 吃哪项读数 | 认哪种敌人 |
|---|---|---|---|
| 破盾尖锋 | 穿透 +2+⌊通透×2⌋ · 伤害 +20% | 通透 void | 重甲与首领（穿透不吃盾的五折） |
| 裂界散射 | 溅射 +1 · 散射 +2+⌊对称⌋ | 对称 sym | 灵体群、破盾的第二个答案 |
| 迅捷节律 | 攻速 +25% · 减速 +0.10+重复×0.10 | 重复 repeat | 冲刺兵、以及「谁都能打」 |

三条设计约束：

1. **每块模块吃一项读数**（`fx(a, es)` 从 `spec.es` 取）。写成常量的话，
   「同一块模块装在不同图形上效果不同」当场塌成一句注释——而
   「**哪座塔配哪块模块**」正是装配台要制造的那个新决策。审美即战力，
   在装配台上当场兑现。
2. **落地只有一个纯函数**：`TD.applyBranch(spec, brId)` 拷一份属性块再改，
   输入那块（在库记录拿着的共享 spec）一个字都不动。折的时候在
   `run.specsOf`（开战）与 `run.add`（局中补塔）**两个口子都要走**——
   漏一处就是「装了模块的塔补进来却不生效」的半修状态（门禁钉着）。
3. **闸门不混**：模块花**结晶**（局外成长，与升级商店同一道闸门），
   辉光仍然只管局内（升级 / 补塔 / 撤收）。`shop.fit()` 做闸门与记账，
   正在局里站岗的塔不给装（部署相位已经按旧属性块落过塔了）。

页面上三张卡把三件事说全：**相性**（吃哪项读数、这座塔是多少）、
**效果预览**（装配前后的属性差，真算的——`applyBranch` 是纯函数，
量两遍就是了）、**装配钮**（结晶不够时禁掉，闸门看得见）。

### 3.3 拆解还料：一把死结的钥匙（本版增量）

`shop.discard()` 现在把这座塔的**元件清单还回库**（`rec.parts` 在提交时记下）。

它不是慈善，是 `_balance.mjs` 的死结体检抓出来的**解药**：起手拼一具又大又贵的
图形（两件殿档能拼出 700+ 辉），成本超过全局部署预算，于是「没有一座塔请得回」；
而尘的唯一水龙头是战斗结算——玩家被锁死在局外，永远翻不了身。
拆解还料把锁打开：请不起就拆，拆了拼一具小的。

两条界不许碰：**「提交消耗元件」不变**（还料发生在淘汰那一刻，不是提交那一刻）；
**流水不受影响**（淘汰只删在库记录，`armoryLog` 是底账，只增不减）。

## 4. 塔防（系统 B，独立系统 · 无限模式）

### 4.1 边界

`core/td.js` 不 import parts/tower/shop。开战拿 `turrets: [{spec, at, pri}]`
纯属性块。画风同源，规则毫无瓜葛。

**两张纸，一条规矩**：塔防从外部收两类纯数据块——
`opts.flux`（阵型的乱流，跟着部署走）与 `opts.buffs`（花园的战斗加成，全程不变）。
两者都在 `td.js` 里被 `fluxOf()` / `buffsOf()` 折成「绝不会崩」的一套标量：
缺省值一律「不作用」，每一项在使用点再钳一次。算这两张纸的是 `run.js`——
它是唯一同时认识两边的地方。门禁直接扫 `td.js` 的源码，`BS.garden` 一个字都不许出现。

### 4.2 无限模式

- 波没有尽头：1~10 波教学骨架；11 波起骨架加码（每波 +armor/+fast，
  5 波一个首领台阶），全局缩放 `waves.scale(n)`：
  HP = 1 + .10(n-1) + .01·e²、速度 = 1+.015·max(0,n-8)、报酬 = 1+.06(n-1)。
- 终局只由基地生命（15）写。休整期二选一：**下一波**继续顶 / **撤离结算**落袋。
- **升级在战斗中也行**（点塔 → 升级）：辉光在击杀里挣，所以它该跟着战斗花，
  而不是只在波间结算。`run.up()` 只挡两个相位——`deploy`（钱是预算不是辉光）
  与 `over`（这一局已经完了）。
  撤离且撑过第 10 波 = won（成就的门槛）。
- 结算收益：尘 = 6×波×加成；晶 = 2×波×加成 (+15 if won)。辉不结算。

### 4.3 局中放塔（本版修掉的老 bug）

旧版 `run.add()` 整个锁在 `phase === 'deploy'` 里，于是「开战」之后军械库里
剩下的塔再也摆不下去——玩家眼睁睁看着库存烂掉，而塔防的乐趣有一半是
「打着打着发现这儿该补一座」。现在三个相位都能放，区别只在**钱从哪儿出**：

| 相位 | 钱 | 能撤回吗 | 军械库 |
|---|---|---|---|
| `deploy` | 部署预算（`build.budget()` + 起手拨付） | 能，全额退款 | `begin()` 时一次性消耗 |
| `battle` / `rest` | **本局辉光**（`b.lux`） | 不能——辉光花了就是花了 | **当场**消耗 |

这条边界必须说清楚：预算是一局的起手资本，辉光是局中挣的。
两笔钱混在一起，「先部署满再开战」和「留着辉光局中补」就不再是两个选择了。
界面上挑选条在三个相位都摆着；门禁在 jsdom 与真实浏览器里各钉一次
（模型放开了而界面没放开，是最难查的半修状态）。

### 4.4 战场上是图形，不是字

旧版格子中间是「塔」与「兵 / 冲 / 甲 / 灵 / 首」五个汉字——玩家读到的是
标签，不是形状。现在：

- **塔画它自己的形状**：`spec.cells`（进化时由 `tower.base()` 写进 spec 的那份）
  经 `figSVG()` 归一化成 SVG，`fill` 按稀有度走（`.fig.r0..r4`），
  与工坊 / 花园同一套色——三处用一套色，玩家才不必重新学一遍「这个颜色是什么意思」。
- **十种敌人各有自己的形状**（`ESHAPE`）：边数即读数——越难缠的边越多
  （三角 / 菱 / 方 / 五边 / 六边 / 八边）。三种不靠边数：群兵是**最小的那个圆**
  （一眼看出「这只不重要，这一群才重要」）、裂胞是**两个圆**（正在分成两只）、
  愈使是个**十字**（它在补自己）。这是给眼睛的提示，不是数值。
- **格子上不许再有字**：`.cell.t u` 那条旧规则（那个「塔」字）一并删掉。

**踩过的坑**：`.cell .fig` 是 `position: absolute`，而 `.cell` 本身没定位——
形状会一路找到 `.bwrap`，把整座塔摊满整张棋盘（截图里是一片蓝色形状）。
对策是给 `.cell` 加 `position: relative; overflow: hidden`。
**这个错只有真浏览器看得见**：jsdom 量不出布局，`getBoundingClientRect()` 恒为 0，
所以门禁在 headless 里同时卡形状尺寸的**上界与下界**（4px < w ≤ 24px）。

### 4.5 塔属性随图案大幅波动（本版）

六项读数的系数按实测分布重新标定（`world/towers.js`）：

| 读数 | 实测区间 | 旧系数 | 新系数 | 塔属性摆动 |
|---|---|---|---|---|
| 对称 sym | .22–1.00 | projStep 3 | **6** | 散射 2–7 弹 |
| 重复 repeat | .13–.76 | rate .5 | **1.3** | 攻速 .97–2.05 |
| 通透 void | .00–.82 | range 2.5 | **5.0** | 射程 2.5–6.6 |
| 匀质 even | .31–.74 | dmg 6 | **12** | 伤害 5.7–13.1 |
| 环络 weave | .00–1.00 | chain 3 | **5** | 连锁 0–5 跳 |
| 轮廓 edge | .26–.84 | melee 5 / hp 60 | **10 / 180** | 近战 2.6–8.4 |

平均值大致与旧版相当（伤害 8.7 vs 6.8、攻速 1.38 vs 1.01），
**变的是摆动的幅度**——旧版伤害只在 5.9–8.4 之间晃，玩家拼什么图形差别不大。
塔的属性 DPS 从约 60 抬到约 98，所以敌血第四轮跟着 +60%
（`world/enemies.js`，见那里的 tuning 注释）——两条曲线要一起动，
只放大塔的波动不改敌血，第 10 波会变成散步。

### 4.6 不同炮对应不同图形：型的战斗签名

这是「游戏体验的关键乐趣」在数值上的落点。十八种型各带一份 `sig`
（`core/parts.js`），由 `tower.base()` 直接加成到属性上：

- `dmgMul` / `rateMul` 是**当场乘进** `dmg` / `rate`，不在 spec 里留没人读的键；
- 其余是加区（`range` / `proj` / `chain` / `splash` / `pierce` / `slow` /
  `dot` / `hp` / `melee` / `auraDmg`）。

于是「主料是十字」和「主料是盘」即使六项读数完全一致，进化出来的也是两种塔
（十字 8 弹 + 多射，盘 +10% 攻速 + 连锁，雷 4 跳连锁，巢 +60 血 + 光环，符 + 减速 + 灼烧……）。
型名因此成了战术语言，而不只是标签。门禁的判据很硬：
**同一具格子表只换 `form`，属性必须变**，且十八种型两两不同。

> 旧的 `pref`（+15% 一个二级属性）被 `sig` 取代。一个扁平的 +15% 撑不起
> 「不同炮是不同东西」——它只让型名有一点点战术意味。

### 4.7 界面强化

- **弹道**：td 每次开火记 `b.beams`（直击/连锁/溅射三色），覆盖 SVG 画线——
  判定仍是纯函数，弹道只是判定的可见面。
- **范围**：点选一座塔，切比雪夫射程的虚线方框亮出；塔详情
  （属性/击杀/目标优先级/升级/撤收）摊开。优先级三档：最前（默认）/最强/贴身。
- **塔条**（battle 独有）：每座塔一行（图形 + 编号 + 等级），点它开详情。
  此前战斗中要打开详情，只能在 22×14 的棋盘上把那一格找出来；
  而点格子那条路还被放塔分支挡着——`sel >= 0`（武装着一座待放的塔）时，
  点塔格先走 `RUN.add`，只换来一句「这一格已经有东西了」。
  现在点击判定里**塔格先于空格**：点空格 = 放塔，点塔 = 看它。
  `deploy` 不摆塔条（塔还不能动，点开只是噪音），`rest` 用完整塔列表。
- **优先级与等级解耦**：目标优先级是**选择态**，不进结构指纹——
  `patch()` 每 tick 补那三个钮的高亮（`skel.pri`）。旧版漏了这一步，
  于是高亮只在等级变化（唯一进指纹的塔字段）时才对，
  读起来就是「升级把优先级改掉了」。
- **波次预告**（下一波组成 + HP 倍率，**也画敌人的形状**，带盾的先画环）、
  **1×/2×/4× 播放速度**、暂停/跳波保留。
- 可复现性不变：同部署同种子，逐 tick 逐字节一致（弹道表也在战态里）。

### 4.8 护盾（本版增量 · 难度与对策一起长）

**第 8 波起，重甲与首领带盾入场。规则只有一条**（`enemies.shieldOf` + `td.hurt`）：

> 护盾先吃伤害；**单体（直击 / 近战）打盾只有五成**，溅射 / 连锁 / 穿透 / 灼烧全额；
> 破盾那一刻溢出的部分按同一折损继续打进血条。

它制造的新决策是「**要不要为破盾留一路非单体火力**」。为什么这条比「再加点血」有价值：

| 只加血 | 加盾 |
|---|---|
| 唯一的答案是「伤害更高」 | 单体伤害被结构性打折，高伤害不再是答案 |
| 升级（只加伤害）依然是万能解 | 升级解不了盾——`_balance` 量到零模块 8 塔 roster 卡在第 14 波 |
| 阵型的 chain/pierce 乱流只是锦上添花 | 那几项**变成破盾波**，读阵型从此有战术含义 |
| 敌人只有一条属性轴 | 盾与敌血同一缩放轴，是难度曲线上的第二层皮 |

可玩性的三道保险照旧：**盾只在第 8 波后出现**（前 7 波足够学会做非单体塔）；
**盾量随波数缩放**（与敌血同一根轴，不是静态属性）；**预告与战场都画环**
（波次预告里带盾的敌人先画一圈青色虚线，战场上盾环 + 顶部的盾条，
血条在底下——两个数字一眼分得开）。结算页把「破盾 n 面 · 盾吸收 m」也报出来，
玩家看得见自己为非单体火力留的位置值多少。

### 4.9 撤收（本版增量 · 摆位不再是赌博）

开战之后能把一座塔摘下来：**返六成辉光，塔回军械库**（从流水 `armoryLog` 恢复一份
独立副本），重新部署要再付一次全价。相位边界照旧：

| 相位 | 动作 | 钱 | 能不能回头 |
|---|---|---|---|
| `deploy` | 撤回 | 全额退款（预算） | 能——还没有沉没成本 |
| `battle` / `rest` | **撤收** | 返六成（本局辉光） | 能重新部署，但要再付全价 |

**为什么是六成**：全额退款会让「先随便摆上去试试」零成本，摆位就不再是决策；
四成过路费让「我摆错了，搬不搬」变成一个真问题。`td.removeTower` 负责把 occ
与光环收拾干净——occ 存的是「第几座塔」的下标，摘过之后全体错位，
所以它重建一遍（塔数是个位数，重建比打补丁便宜也更不容易错）。

## 5. 图形花园

**16×12 起步、没有设计上限**的常驻板。本版两处大改：

### 5.1 无限延展

旧版钉死 12×8——种满就种满，玩家对着一块满了的园子无事可做。
现在园子按**已种格数**一圈一圈向外长：每满 `PER_LEVEL`（16）格，
长宽各 +`STEP`（2），层数记在板子上（`garden.lv`）。

- **只扩不缩**：挖走元件只减格数、不减层数。否则「挖一格园子就塌一圈」
  会把玩家种下去的东西连座端走。门禁断言挖空之后层数与尺寸都不变。
- **不需要迁移**：已种下的元件永远在新界内，扩容不搬移、不清理任何已有图形。
- 手滑上限 400 层纯粹是防呆，不是玩法上限（要到那儿得有六千多格）。
- 老存档没有 `lv` 一栏：`bus.norm()` 按已种格数补一份（`grow()` 是单调的，补一次只会继续往上长）。

### 5.2 功能换成战斗辅助

旧版是「随真实时间滴答的被动采集尘」——一个挂在墙上时钟上的水龙头，
玩家什么都不做也在涨。本版起花园只服务**战斗**：

| 类 | 加成 | 来源读数 |
|---|---|---|
| **战斗掉落** | 辉光掉落 +% | 环络 weave |
| | 尘晶掉落 +% | 轮廓 edge |
| **增益** | 伤害 +% | 匀质 even |
| | 攻速 +% | 重复 repeat |
| | 射程 + | 通透 void |
| | 暴击率 +% | 对称 sym |

于是花园从「放着不管也会涨的后台」变成「我为下一局准备了什么」——
它改变的是**这一局怎么打**，而不是账本上的一个数。
`garden.sweep()`（墙上时钟结算）连同 8 个调用点一起删掉了：
留着 8 个空转调用，正是这一部反复要避免的腐烂。

### 5.3 计量单位是「件」，不是「整园那一具根」

上一版按**整园那一具根的峰值**给一类加成。实测踩了自己写的失败信号 **G2**：

```
种满 128 件：  伤 0.0  速 0.0  射 0.00  暴 0.0  辉 147.6  尘 0.0
种第 2 件时：  暴击 10.1% → 0.0%   （整园对称度 1.00 塌到 0.22）
```

两条毛病，一条比一条致命：

1. **六类里五类恒为 0。** 贴着根种的规矩让整园恒为一具根，而「一具根只有
   一个峰值」——累加「具数」没有意义，于是「六类加成」退化成「一类加成」。
2. **越种越弱。** 根长大了峰值会换人（对称根长着长着变成环络根），换人的
   那一刻那一类当场归零。旧版甚至把这条写进了测试注释里当特性读
   （「换人的那一刻总量会掉一点——那是真的，不是 bug」）。

所以计量单位换成**件**：`insts()` 给每一件自己那六项读数（由形状决定，
种下之后**再也不会变**）。于是：

- **单调**：种一件多一份，只会往上加，不会吃掉别人的那一份。
  门禁现在测的是**六项各自严格不回退**（`smoke.mjs`），不再是「总量总体在涨」。
- **多类**：每件自己的峰值**全额**、其余五项按 `SUB = 0.35` 出力。
  为什么要折：全项全额会让「随便种一件」等于六类各 +10%，
  「这一件是对称的所以它给暴击」这条因果就被抹平了。
- **面板**：六类各占一行——旧版压成两行文字，正好把「五类恒为 0」藏住了。

**一份「满强度贡献」= 读数 × 16 格 × 权重。** 权重三处：
主项 1.0 / 副项 0.35 / 离根 0.5。

### 5.4 苗床：加强前期的那一脚

最早种下的 `NURSE_CELLS`（96 格 = 6 圈）**额外再给一半**出力：

```
out = GAIN · (raw^0.6 + 苗床^0.6 × 0.5)
```

为什么是「按格划一段」而不是「全园乘一个随园子变大而衰减的系数」：
后者实测会让苗床的衰减**跑赢读数的增长**——种第 2 件时射程从 0.472 掉到 0.462，
等于把「越种越弱」又请回来了。按格划段之后两份原料都只增不减。

窗口按**种植顺序**算，所以挖走早年的件，后面的件会**顶进苗床**——
「我要不要把这一片挖了重种」因此是一个有数字可看的问题，而不是玄学。

实测（贪心铺，同一批元件）：

| 件 | 格 | 伤害 | 攻速 | 射程 | 暴击 | 辉光 | 尘晶 |
|---|---|---|---|---|---|---|---|
| 1 | 12 | +8.6% | +7.9% | +0.49 | +15.1% | +10.2% | +10.2% |
| 3 | 23 | +11.3% | +9.3% | +0.49 | +19.0% | +15.9% | +12.8% |
| 6 | 53 | +18.3% | +16.9% | +0.49 | +25.7% | +15.9% | +27.8% |
| 20 | 142 | +32.3% | +25.9% | +0.49 | +36.1% | +22.9% | +46.9% |
| 128 | 832 | +77.2% | +69.7% | +1.68 | +76.2% | +67.6% | +102.5% |

旧版第一行是「暴击 +10.1%，其余五项 0.0」——这就是前期加强的全部含义。

### 5.5 离根

园子里有别的件、而它所在的那一块里只有它一件的，出力 **×0.5**
（园子里总共只有一件时不算——第一件本来就无处可贴）。
挖断才会造出这种件，所以它是「挖之前先想」的那条代价，
也是「贴着根种」这条放置规矩的**回报**——否则它只是一条约束。
加成折成 `buffs()` 交给 `run.js`，与乱流同一套规矩（纯数据块、逐项钳一次）。

## 8.1 语言层：中文即键，两种语言（本版重做）

上一版把语言层拆成「单语直通」——`get()` 原样返回中文，并把这件事当成优点写在这里。
本版把它**重新装上**，而且装法是当初留下那个调用点的目的：

- **中文是源**：`T('战斗')` 里的中文串**就是键**。所以重做语言层没有动十三页里的
  任何一处调用（三百多处），只改了 `core/i18n.js` 一个文件 + 加了 `world/i18n/en.js`。
  两栏键表（`key: {zh,en}`）看起来更整齐，代价是三百多处全得改一遍——
  这正是「拆掉它不用动任何一页」的反面用法：**装上它也不用动任何一页。**
- **表项自带 `en`（说明栏是 `den`）**：稀有度 / 型 / 特质 / 敌人 / 升级 / 成就 /
  六种形变，它们的名字与说明是**造型语言的一部分**，
  所以翻译只写一次，由 `I.term(row)` 按语言取。`en` 是名字、`den` 是说明——
  混用会把「一条直杠，长而薄」显示成「BEAM」。
- **查不到就退回中文**：宁可让漏译以中文形式露出来（看得见），也不要让它变成空白。
- **派生名**：进化体的名字（`进化体·拱 003`）不是数据，是**派生的**（型 + 编号）——
  显示时按当前语言现算。存档里那份 `nm` 留着（流水要留档），但界面不读它。

### 门禁两条（这是「公开展示」的硬判据）

| 门禁 | 判据 | 抓的是 |
|---|---|---|
| **覆盖**（smoke.mjs） | 把源码里所有会走 `T()` / `H.kv()` / `H.head()` / `I.fill()` 的串抽出来，逐条查词典；再查 `#` 占位数量是否一致 | 加了新界面忘了上语言；译文少一个数字 |
| **逐页扫描**（smoke_ui.mjs） | 切到英文，十二页逐页挂载，把正文拼起来找 CJK；有一处残留就红（每页报前 6 处） | 渲染路径上的漏译——它量的是**结果**，不是源码 |

抽取器有两条必须有的能力，都是被真实的漏译教会的：
**看得懂跨行拼接**（长段落写成 `'第一句' + '第二句'`，运行期的键是拼完那一整串）；
**跳得开字符串里的逗号**（`i + ' , ' + j` 里那个逗号会把扫描器骗出一堆假键）。
另外两类它**看不见**，所以要单独查：页面标题走 `T(注册表字段)`、动态键走三元表达式
（`T(midRun ? '补塔…' : '挑一座塔')`）——前者由界面门禁查注册表，后者靠逐页扫描兜底。

**边界（如实写在 README 里）**：`essence` 里那些判据的**散文说明**（测量页悬停才展开的那段）
仍是中文。它们是这一部的文学层——机翻会把「底之所以为底，因为它不再往上长」翻成一句废话。
界面上看得见的部分（含每一页的开场白、图鉴的公式、成就的「还差什么」）全部有英文。

### 9.2 本版翻车与对策

- **「无法部署元件」**：工坊/塔防在 mouseenter 里整页重渲染，真实浏览器光标一动
  就换一轮节点，click 落在公共祖先上永远不触发。jsdom 不动鼠标，门禁全绿照样翻车。
  对策进结构：ghost 只碰 class、试算只写固定盒子；门禁补 mousemove→空格链。
- **试算的布尔坑**：`canPlace` 的 OK 是空串，`!canPlace(...)` 恒真。
  空串哨兵一律 `!== ''` 判。
- **词典注入两次打偏**：`replace('{', ...)` 会命中 `|| {}`——注入词条必须锚定
  `maps.xx = {`，且 `git checkout` 会连带抹掉未提交的翻译（这次的 40 条旧键就是这么
  丢的，已重补）。
- **导航排序按字符串比**（本版）：`registry.list()` 用 `localeCompare` 排 `n`。
  军械库编号从 `'9'` 提到 `'10'` 之后，`'10'` 因为字符 `'1' < '2'` 被排到了
  `'2'`（库）前面——截图里一眼看到「1 工坊 / 10 军械库 / 2 库」才发现。
  对策：排序键按数值比，非数字才退回字符串；门禁逐对检查相邻项数值递增。
- **老存档补偿判错了对象**（本版）：`armoryLog` 的「缺栏补偿」写成判
  `b.armoryLog`（`blank()` 出来的默认对象），它已经有空数组，`Array.isArray`
  恒真，补偿分支一次都进不来。对策：判在**原始存档对象** `o` 上。
  这是「先填默认值再判断缺失」这类写法的通用陷阱。
- **缓存与全局升级打架**（本版）：`tower.attrs()` 按图形签名缓存，而「手感」三条
  升级是全局的。若把升级乘进缓存，买完之后老塔永不刷新。对策：`base()` 走缓存、
  修正段每次都算；门禁断言买前买后同 part 的 dmg/rate/range 递增。
- **拆页要拆干净**（本版）：抽卡与升级搬去商店页后，库页必须**一个 `draw:*` /
  `buy:*` 按钮都不剩**。半拆状态最难查，门禁直接扫这两页的按钮集合。
- **尺寸探针要用"件体越界"量，不能用"锚点越界"量**（本版）：
  `place(i, at)` 的 `at` 是元件**包围盒左上角**，不是单格。元件有宽高
  （0 号件 4×4、3 号件 5×7，池里最小的一档是 4 号件 2×2）。
  最初拿 0 号件、锚点放在 `(w0-1, 0)` 去量「扩容后界变宽了没」，
  件体从 `w0-1` 伸到 `w0+2`，扩容成 16 之后仍越界——量出来的是「这件太大」，
  不是「界没变宽」。对策：尺寸探针固定用池里最小的 4 号件，
  并加一条反证（同一件放回界内不许报「超出图纸」），
  否则那两条界断言本身是误判。**测试探针选错了不会报错，只会静默地量错东西。**
- **`mark()` 只置脏、`tick()` 才重画**（本版）：工坊页订阅 `gain` 之后调 `mark()`，
  真正的重画在 `tick` 里（时钟驱动）。UI 门禁里买完升级不推时钟就去数 DOM，
  数到的是旧网格（126 格），差点被当成「订阅没生效」。
  作品是对的——真游戏每帧都 tick；测试要像真游戏一样推一格时钟。
- **`forget()` 只清了一半缓存**（本版）：`tower.forget()` 清了 `CACHE`（读数）
  却没清 `ACACHE`（属性）。于是「改完 SCALE 表调 forget() 再量一次」
  量到的还是旧值——连量三遍数字一模一样，还以为自己没改到位。
  这个坑极难发现：生产环境里图形签名是稳定的，缓存永不失效也不出错；
  只有调系数、做实验、写测试才会踩上，而那时它会**静默地告诉你「改没用」**。
  对策：两个缓存一起清；门禁断言改系数 + forget 之后读数必须变。
- **`dmgMul` 写进了 spec 却没乘进 dmg**（本版）：型签名里 `s['dmgMul'] = 1.10`
  只是新开了一个没人读的键，`dmg` 一动不动。乘区必须**当场作用**，
  别在 spec 里留装饰性字段——留了也不会报错，只会让你的设计 quietly 不存在。
- **测试的玩具塔杀不动敌人**（本版）：乱流耦合测试用 `dmg: 3` 的塔，
  敌血第四轮调到 67 之后它 300 tick 内一只都杀不死，于是强/弱乱流都是 0:0，
  断言 `ka !== kb` 静默地变成一个永假式。**量不出差别时，先问探针够不够强。**
- **绝对定位的 SVG 找不到父级**（本版）：`.cell .fig` 是 `position: absolute`，
  而 `.cell` 没定位，形状一路找到 `.bwrap`，把整座塔摊满整张棋盘。
  jsdom 量不出布局（`getBoundingClientRect()` 恒 0），**只有真浏览器看得见**。
  对策：`.cell` 加 `position: relative; overflow: hidden`；
  headless 里同时卡形状尺寸的**上界与下界**（4px < w ≤ 24px）。
- **半修状态：模型放开了、界面没放开**（本版）：`run.add()` 放开到局中之后，
  挑选条若还只在部署阶段渲染，玩家照样放不了塔。这类错最难查——
  接口层说「可以」，界面层说「不行」。门禁在 jsdom 与真实浏览器里各钉一次，
  而且钉的是**点了之后塔数真的 +1**，不是按钮存在。

| 门禁 | 结果 |
|---|---|
| `test/smoke.mjs` | **306 项通过**（原 246 + 型签名 14 + 局中放塔 11 + 花园延展 12 + 幂次曲线 12 + 花园进战斗 10 + 缓存失效 3） |

| `tools/headless_check.mjs` | **60 项通过**（真 Edge：原 40 + 战场图形 11 + 花园延展 9） |

合计 560 项（上一版 435）。本版新增的断言值得单独点名：

1. **扩容必须用"件体越界"来量，不能用"锚点越界"来量**：
   元件是有宽高的（0 号件 4×4，池里最小是 2×2）。一开始拿 0 号件当探针，
   锚点放在 `w0`，量出来的却是它在基准板上就放不下——**是探针放错了地方，不是界错了**。
   改法：尺寸探针固定用 4 号件（2×2），并加一条反证
   （同一件放回界内不许报「超出图纸」），否则那两条界断言是误判。
2. **旧图纸不搬家**：扩容前放一件记下 `cells` 的 key 与总格数，
   扩容后 key 还在、格数不变。没有这条，「扩容清板」这种负体验会静默通过。
3. **同一具图形换主料必须出不同的塔**：拿一具固定的 3×3 实心格表，
   逐个型过一遍 `tower.attrs()`，断言十八种型**两两不同**。
   这条是「不同炮对应不同图形」的硬判据——型名若只是标签，它当场红。
4. **局中放塔必须真的多一座**：jsdom 与真实浏览器里各点一次挑选条 + 合法落点，
   断言 `battle.towers.length + 1` 且军械库当场清空。
   只断言「按钮存在」抓不住半修状态。
5. **战场格上不许有字**：把 `.bgrid .cell` 的 textContent 全拼起来，
   正则扫「塔兵冲甲灵首」。这条防的是「某个新页面又随手写了个 `<u>塔</u>`」。
6. **形状必须守在格子里**：headless 里同时卡 4px < w ≤ 24px。
   下界防空 SVG，上界防父级没定位导致形状摊满棋盘——后者 jsdom 永远看不见。
7. **幂次曲线的三个不变量**：一级与旧版逐字相同、四级明显低于复利/线性、
   逐点增量递减（真凹，不是折线）。这条一坏，升级 / 塔等级 / 花园三处一起静默变回线性。
8. **常量别名必须不存在**：断言 `BS.shop.COLS === undefined && BS.shop.ROWS === undefined`。
   留着常量迟早被当成"当前尺寸"用——所以它被删掉，并由门禁保证它不会被加回来。
9. **当场重画**：UI 门禁里买完「图纸扩容」后推一格时钟，再数 DOM 的
   `.wgrid [data-c]`；真实浏览器里还额外量了 `--cols` 与格子实际宽度（26px），
   防的是「格数对了但网格塌成一列」这种只有真浏览器看得见的错。

### 9.5 headless_check 抓到、而 jsdom 永远抓不到的两件事

1. **视口坐标**：`Input.dispatchMouseEvent` 用的是视口坐标。`.ax-fl` 排在滚动区下方
   ~1000px 处，不先 `scrollIntoView` 就派发鼠标事件，坐标会落在别的元素上，
   于是误判「悬停坏了」——代码是对的，量错了地方。
2. **Windows 路径分隔符**：`path.join` 产生反斜杠，`f.startsWith(ROOT)` 做越权检查
   会把每个请求都判成越界，于是 `/index.html` 也 404、整个检查全红。
   统一 normalize 成正斜杠再比。

这两条都不是作品的 bug，是**验证工具的 bug**——但它们的症状都长成「作品坏了」。
记在这里，免得下次再花时间往作品里找。

另有一条**只有截图能发现**的：导航顺序。断言只看「末位是不是 settings」，
看不出「10 混进了 2 前面」——那是靠肉眼看截图才逮到的（见 §9.2）。
所以 headless_check 现在对商店页、军械库页、工坊页各留一张截图，不只为好看。

### 平衡实测（8 种子 × 4 局生涯；元进度全零）

| 量 | 数 |
|---|---|
| 新玩家首局失守波数 | **中位数 14**（范围 13–14）——第 8 波起带盾之后，1 座塔的 roster 卡在这里 |
| 末局（第 4 局）失守波数 | spread 10 · focus 12 · none 8.5 · fit 12.5——装配台取向领先 |

| 固定 roster 的策略敏感度 | spread / focus / none / fit 中位数都是 14——**第 14 波是个断崖，升级取向跨不过去**（见下） |

三条结论，一条比一条重要：

1. **护盾把「伤害」这条万能解按住了。** 升级只加伤害（`levelMul`），
   盾把单体伤害结构性地打五折——所以零模块的 roster 无论怎么升级都卡在第 14 波，
   而装配三块模块能把同一批塔推到第 22 波。**模块不是加成，是另一个维度**。
2. **升级取向（摊平 / 集中 / 不升）在第 14 波断崖前没有差别**——这是本版
   诚实记下的**否定结果**。它不是「旋钮坏了」：三者在断崖之下都能多撑一两波，
   只是断崖把差异吞掉了。真正的分水岭是「有没有为非单体火力留位置」。
   `_balance.mjs` 直接把这句话打出来（「没有差别，这个旋钮没在制造决策」），
   下一版要动难度曲线时，先看这一行。
3. **经济偏紧是真的**：一个 4 局生涯里 roster 只长到 1–3 座（塔开战即消耗，
   6 尘/波只够每局再拼一座两件的塔）。所以「攒件 → 一次满编」是这一部的
   真实玩法节奏，而**撤离**（撑过 10 波就拿 15 结晶犒赏）是它唯一的经济加速器——
   §9.3 的那条待验证项，答案是「偏紧，但保底机制（拆解还料 + 撤离犒赏）够用」。

### 本版翻车与对策

- **`_balance.mjs` 的探针选错了粒度**（本版新工具第一次用就踩）：
  贪心装配器把全部库存拼成**一具**巨型图形（5 件 → 1 座 221 辉的塔），
  于是「每局一座塔」的假象被当成游戏结论。真实玩家会拼一排小塔铺预算。
  对策：装配器改成「一座两件、交到容机上限」，roster 才会随生涯长大。
  **探针的粒度错了，量出来的数字会自洽地骗人。**
- **固定 roster 名不副实**（本版）：`store.draw` 内部是 `Math.random`，
  没法播种，于是「同一个种子」下每个取向拿到的元件批完全不同——
  比较的其实是家当不是策略。对策：按 `hash(seed)+序号` 规则确定性取件，
  只取小件（两件殿档能拼出 700+ 辉，全局预算请不起，整批探针会作废）。
- **`bus.save()` 序列化的是闭包里的 `state`**（本版截图时踩）：
  测试与临时脚本整体替换 `BS.bus.state` 之后，闭包那个还是旧对象，
  于是 `save()` 写出去的是空存档（截图页一片空白，还以为是渲染坏了）。
  对策：造存档走 `dump()` / `restore()` 的正道，别绕过它。
- **存档键与页内导航**：`Page.navigate` 只改 hash **不会重载页面**，
  三个 hash 截出来是同一张图。对策：加一个 cache-busting 查询参数强制重载。
- **真实点击门禁带摇签**（本版）：`newRun('')` 的种子是 `Math.random`，
  局中补塔要花辉光，摇少了就静默失败，整节假红。对策：那一节只管界面链
  （挑选条 → 亮落点 → 点格子 → 真多一座），钱给够；辉光闸门在内核门禁里钉。

### 9.7 三条用户 bug 的修复（本版）

**一、点原件之后切标签，元件消失。** 真因不在点击，在 `mount`：
工坊与花园的 `mount` 里写着 `hand = -1`——而「拿在手上」那一下已经
`store.takeOne()` 把这枚元件从库里拿出去了。于是切走再回来，那枚就凭空蒸发。
对策：两页都加 `dropHand()`，**离页（unmount）与进页（mount）各还一次**——
unmount 是语义正位（离开这一页就该放手），mount 是兜底。
门禁在界面门禁与真实点击门禁各钉一次往返（真点导航切走再切回来，量库的数量）。

**二、战斗过程中无法给炮塔升级。** `run.up()` 原先只认 `rest` 相位，
塔详情里的升级钮也只在休整期渲染——于是「打到一半发现这座该升」没有出口。
对策：`up()` 放开到 `battle`，只挡 `deploy`（钱是预算不是辉光）与 `over`；
按钮在两个相位都摆。门禁分三层钉：内核验相位（战斗中成功、部署/结算被拒）、
界面门禁与真实点击门禁各验「点塔 → 出现升级钮 → 点它 → 等级真 +1 且辉光真扣」。

**三、存档与重置搬进设置页。** 原先「存档」挂在顶栏、「清空存档」埋在卷宗页
（那一页本版已撤，战绩并入图鉴），
而且那颗**点一下就直接清**（既没有二次确认，也没有一句「你在清掉什么」）。
对策：新开 `world/mods/settings.js`（导航 12）——
· **一处**：顶栏撤掉存档钮，记录页撤掉导出/清空（只留一颗指路钮）；
· **看得见**：重置前先摊出这一份进度（局数/胜场/最高波/在库/流水/抽卡/库存/资源/花园）；
· **回得来**：导出为文本 + 导入读回（`bus.encode/decode/restore`），
  重置因此不是不可逆的事故；重置本身要**二次确认**（先亮确认、可「算了」）。

这一版新增的翻车记录（都进了门禁）：

- **点了会重画的按钮，旧节点当场游离**：真浏览器里第一次 `click(save)` 之后
  整页 `innerHTML` 重画，先前抓在手里的 `export`/`reset` 节点已经不在文档里，
  再点它们等于什么都没点——headless 里当场两条假红。对策：**每次点击前重新取**。
- **时间戳不能过 `| 0`**：设置页「上次写入」显示 `1970-01-01`——
  13 位毫秒被按 32 位截断了。这个错 jsdom 抓不到、断言也不痛，
  **是截图逮到的**（数字不抛错，只有眼睛看得出不对）。
- **`fresh()` 是空库**：`bus.blank()` 的 `inv` 是空的，起手礼包由 `startKit()` 发；
  内核门禁里「拿一枚」的探针想当然地以为库里有三枚，于是量到 0。对策：探针自己铺料。

## 9.8 本版实测：删掉指针宇宙，换上阵型 / 质变口 / 邻接回路

### 9.8b 按钮点不了 + 战场扩容

**「按钮点不了」的根因不是 CSS**（`.bovl` 一早就有 `pointer-events: none`），
而是**战斗中每 160ms 整页重画**：`host.innerHTML` 一换，mousedown 与 mouseup
就落在不同节点上，浏览器根本不出 click。jsdom 的测试是同步派发事件的，
所以三道门禁一直是绿的，而真人是瘸的——**这一类 bug 只有门禁的判据错了才查不出来**。

对策是把战场页分成两层：**结构指纹**（相位 / 选中 / 塔数 / 等级 / 形变 /
暂停 / 倍速）不变就只补数字与格子，指纹变了才重搭骨架并重新绑事件。
`smoke_play.mjs` 新增的那一节判据只有一条，但它必须是真的：
**跑过时钟之后，那个按钮还是同一个节点**。

战场同时从 16×10（160 格、20px）扩到 **22×14（308 格、24px）**。
理由：摆位太挤的话「谁挨着谁」这门学问还没展开就用完了。
`_balance.mjs` 复跑：首局失守中位仍是 14，模块仍值 +2.5 波，无死结——
面积翻倍被「路径也跟着变长」抵掉了大半，难度墙基本没动。

| 门禁 | 结果 |
|---|---|
| `test/smoke.mjs` | **455 项通过**（阵型 2 节 + 阵型组 1 节 + 质变口 4 节 + 邻接回路 2 节；指针宇宙那八节整节删除） |
| `test/smoke_ui.mjs` | **223 项通过**（页面数 13 → 12，「指针宇宙不许回来」一条硬判据） |
| `test/smoke_play.mjs` | **128 项通过**（浮层那一节换成「读数即裁判」；新增「战斗中按钮点得下去」一节） |
| `test/_balance.mjs` | 首局失守中位由 12.8 挪到约 14：阵型乱流不再是零均值扰动，而是偏正的一片加成，难度墙因此往后挪了一格。模块仍值 +2.5 波，取向之间仍有 0.5~1.5 波差，无死结 |

① `_balance.mjs` 的 AI 最多把塔升到 2 级，所以它**从来没走到质变口上**——
那两道口的数值还没被平衡探针量过，目前只有门禁在守（六种形变各自改规则的行为断言）。
② 「spread vs focus 没有差别」是老结论（DESIGN §2.3），本版复跑依旧如此，
它不是这一版引入的，也还没修。

### i18n 这一版踩到的坑（全部已钉进门禁）

1. **抽取器只认单字面量 → 每一页最显眼的那行开场白全漏**。长段落写成
   `'第一句' + '第二句'`，运行期的键是拼完那一整串，正则抽到的是片段。
   对策：抽取器改成**吃掉拼接链**。这一条不修，漏译会精确地落在每页标题下面那一行。
2. **字符串里的逗号会把扫描器骗出假键**：`H.kv('坐标', i + ' , ' + j)` 让参数扫描
   在引号里的那个逗号上断开，于是抽出一条 `"+ j, T("` 这样的假键。
   对策：跳参数时要**逐字符跟踪引号状态**。
3. **在错的门禁里查注册表 = 假绿**：我一度把「每页标题都有译文」写进内核门禁——
   它遍历 `reg.list()`，而内核门禁只加载 `core/`，注册表是空的，于是那条断言
   **永远为真**。对策：挪到界面门禁（那里十三页真的挂了）。`APEX` 这一条漏译
   就是被它逮到的。
4. **`H.kvR` 不取词**：它是「调用方已经定稿」那一组（历史原因）。
   上一版指针宇宙页整条头栏用的是 `kvR`，于是「刻度 / 面积 / 环 / 时钟 / 入 / 出 / 拍」
   在英文界面里全是中文。对策：那几行的键显式套 `T()`。
5. **定版块里存着当时语言**：乱流块在换波时被冻住（`freezeCombat`），
   里面的刻度名是那一刻的语言。切语言不会让已经冻住的块改口。
   对策：显示时按当前语言**回译**（刻度名进词典），定版承诺不受影响。
6. **历史日志与已存名字不该跟着切**：`state.log` 与 `rec.nm` 是**档案**——
   切换语言时它们保持原样（图鉴页的最近记录、早先造的塔名）。前者在扫描里被明确排除，
   后者改成**派生名**（型 + 编号现算），于是新造的塔不会再带中文名。
7. **探针一轮只报一处 = 修一轮露一处**：逐页扫描最初只报每页第一个中文串，
   十三页能拖十几轮。对策：每页一次报 6 处——**探针要一次把话说全**。
8. **探针要按被测的量配料**（又一次）：验「外源拓张」时把结晶给到 100000，
   外源读数直接被饱和钳在 1.6，量出来「纹丝不动」；验「顺流校准」用的帧太强，
   正负两侧都撞在上限上，也是纹丝不动。**量不出差别时，先问探针给过头了没有。**

## 9.10 本版实测：运营三件事 + 重塑（局外成长与困住重置）

> 改动的起点不是「加内容」，是**一处已经死掉的决策**：
> 旧版失守与撤离的结算**逐字相同**，于是最优解是「永远点下一波直到死」，
> 撤离按钮是一个假决策。修它之前，加什么都是往一栋没有门的房子里搬家具。

### 判据（先写清楚什么算成功）

| 编号 | 判据 | 实测 |
|---|---|---|
| O1 | 撤离与失守必须是两笔账，玩家能指出差在哪 | 失守 六成 / 无犒赏 / 阅历记一半；结算页三栏全写出来 |
| O2 | 战况的倍率**看得见且当场变** | 勾一条厚甲，条上倍率 1.00 → 1.18，取消也跌得回去 |
| O3 | 指令三选一**每条都有付** | 十条逐条查 `pay`，门禁一条不过就红 |
| O4 | 阅历**逐条列得出来源** | 波数 / 深水 / 击杀 / 撤离 / 战况 ×N / 失守 ×0.5 六行 |
| O5 | 困住**判定得了**，且出口长在玩法里 | 本条**已被 §9.11 推翻**：判定权交回玩家，`stuck()` 删除，重整改为常驻 |
| O6 | 局外成长优先给**横向解锁** | 20 个节点里 7 个开的是新选项（候选 +1 / 重掷 / 高级指令 / 契约 ×2 / 抚恤 / 深水） |

### 三条值得记下来的

1. **「最优解是永远往前」是一种无声的死亡。** 它不会报错、不会崩、门禁全绿，
   玩家只会觉得「这个游戏没什么可想的」。查这类病只有一个办法：
   **把两个选项的收益算出来摆在一起**——一摆就看出它们相等。
   同理，`_balance.mjs` 里「focus vs none 差 0 波」也是同一种病
   （那个旋钮没在制造决策），两种病都得靠**摆在一起**发现。
2. **「有得必有付」是硬要求，不是文案风格。** 第一版指令表里我差点留下
   「加班：免费升一级」这种纯收益项——它的问题不是数值太强，而是
   **它让三选一退化成挑最大的那个**。现在每条都写两行（得 / 付），
   连「潜伏」这种纯防守项也要付（报酬 ×0.85）。
3. **横向解锁比纵向数值更值钱，但更难写。** +10% 伤害是三行代码；
   「候选从 3 张变 4 张」要动 UI、要动候选生成、要存档、要门禁。
   值钱的地方在于：前者玩十局就感觉不到，后者**每一局都在提醒你
   上次点亮的那个东西还在**。

### 一些没做（诚实披露）

- **没有做局内地图像 IS 那样的分支路线**——塔防没有地图可走，
  把地图折成三张卡是妥协，不是等价替换。
- **战况只有九条、三档**：再往上加会变成「每次开局都要读一遍说明书」，
  而开局的摩擦比难度本身更容易赶人走。
- **重塑树是单前置**：多前置会让玩家在脑子里做拓扑排序，
  而那不是这一页该收的乐趣。
- **重整没有做「部分保留」**（比如留下花园）：一次只清一件事，
  说清楚了才敢按；想留花园的话，那是另一个节点该讨论的事。

## 9.11 本版：塑造→重塑 · 重整改为手动且按下即结算 · 敌人十种

> 三件事里只有第三件是「加内容」，前两件都是**把一处已经写错的东西改回来**：
> 第一件是名字，第二件是「谁来做这个决定」。

### 一、塑造 → 重塑

全量改名（页面标题、重塑树、日志、注释、README / DESIGN、测试断言、英文词典的键）。
**《明日方舟》集成战略的「认知塑造」这个原词不动**——那是别人的术语，
改它等于把出处也一起擦掉。内部页面 id 仍是 `shaping`（它不出现在玩家眼前，
换它要动的调用点比改名多一个数量级，收益为零）。

### 二、困住不由机器判定；重整常驻，按下即结算这一局

旧版 `stuck()` 只认**一个**死结形状（没件 + 没塔 + 尘不够抽一发）。
它的问题不是认得准不准，是**它替玩家做了那个决定**：

- 玩家不想再打下去的局面有一百种——手里剩一堆拼不出东西的废件、
  塔都在但这一套打腻了、或者只是想换一种活法。那一个形状之外的九十九种，
  界面一声不吭。
- 反过来，它认准的那一种，界面开口说「你被卡住了」——而判断的根据
  是存档的形状，不是玩家的意愿。**机器一开口，玩家就不做这个决定了。**

所以：判定删掉，那一键**常驻**，什么时候按由人定。界面只写代价，不写判词。

配套的半件事：**按下即结算这一局**。旧版直接丢弃 `state.run`，
打了一半按重置等于白打。现在：

| 按下的时刻 | 口径 |
|---|---|
| 波与波之间（休整期） | **撤离**——全额 + 剩余基地折算 + 阅历全额 |
| 交战中 | **失守**——六成 + 无折算 + 阅历减半 |

交战中按**不许**比守到休整期更划算——否则「打到一半按重置」就是躲掉失守的
捷径，而 §9.10 的 O1（撤离不能是假的）会被同一条路重新捅穿。
配给也从「直接赋值」改成**保底**：`max(现有, 配给)`。叠加的话
「打一局 → 按重置」就是一台抽水机。

### 三、敌人 5 种 → 10 种

| 新增 | 逼什么 |
|---|---|
| 群兵 SWARMLING | 单只没血，成群才成立：单体火力会被淹掉 |
| 疾甲 LANCER | 又硬又快：减速拖不住，单体也啃不动 |
| 裂胞 SPLITTER | 死时炸出两只群兵——**杀在哪儿**成了决策 |
| 愈使 MENDER | 每秒回 7 点：小刀子割不动，要么一发打穿要么别碰 |
| 壁垒 BULWARK | 单体只剩三成还带厚盾：这一局必须留一路非单体火力 |

前五种管**属性分工**，后五种管**时间与地点**。十种一起，波次预告才值得看。

两个新字段是**纯数据**：`regen` 与 `split: {id, n}`。它们与 `hp` / `speed`
同一种东西——表上写多少就是多少，`td.js` 里没有一句「如果敌人是裂胞那么」。
**出生与分裂共用同一个 `spawnAt()`**：分开写两遍的代价是「分裂出来的不缩放
血量」这种 bug，而它只在第 20 波之后露面，那时没人会怀疑是新兵太脆。

波次也跟着变：新种类按波入场（11 疾甲 / 14 裂胞 / 15 愈使 / 16 壁垒）之后
**常驻**；第 11 波起每波有**主题**（潮 / 疾 / 甲 / 灵 / 攻，五波一轮，
主题那一路抬五成并写在预告里）。旧版第 11 波与第 12 波只是数字不同、
问法完全一样，预告也就没有看的必要。

### 判据

| 编号 | 判据 | 实测 |
|---|---|---|
| E1 | 重整那一键**常驻**（不认困住） | 库里有件、军械库有塔、局还在打，钮照样在 |
| E2 | 按下即结算这一局 | 休整期按 → `lost === false`，阅历涨；交战中按 → `lost === true` |
| E3 | 配给是保底不是叠加 | `dust = max(现有, 配给)`，门禁查 `>= kit.dust` |
| E4 | 两种新机制真的生效 | 裂胞死后，群兵出现在**父代死的地方**（`pos > 0`）；愈使每秒回血且**不回过上限** |
| E5 | 相邻两波不是同一张脸 | 11–15 波五个主题互不相同，16 波回到 11 波那个主题 |
| E6 | 难度不被顶穿 | `_balance`：spread 18.0 / focus 16.5 / none 16.5→16.5 / fit 20.0；模块仍值 2.5 波；死结体检 32/32 |

### 顺手修掉的一个老 bug

`tickOnce()` 的 DoT 分支：致死时 `hurt()` 已经把那只敌人摘出队列了，
紧接着的 `splice(i, 1)` 摘掉的是**左移一位后落到 i 上的那一只**——
它这一拍已经处理过了，于是被无声删掉：不掉辉光、不记击杀、也不到站。
修法是先确认 `b.enemies[i] === e` 再摘。它在有灼烧塔的局里一直生效，
而表现只是「偶尔有敌人凭空消失」，属于那种**不会报错、只会让手感发飘**的病。

## 9.12 本版：删掉卷宗 · 图鉴挪到最底部并扩写

**用户原话**：「卷宗删了，图签挪到最底部并更加详细。」

### 一、卷宗删了，但战绩没有跟着删

删一页不等于删一份履历。`meta.history` 是**数据**，卷宗页只是它的投影；
页面可以撤，账本不清零——这一部连「彻底重置」都要二次确认，
没道理让一次页面整理把上一局的种子与波数抹掉。

所以战绩连同「最近记录」一起搬进图鉴，图鉴从「参考书」变成
最后一页的「**档案 + 宪法**」。导航顺序上图鉴垫底是故意的：
参考与档案不该挤在工坊与战场之间——玩家查规则是**主动来查**的，
那就不该挡在日常动线上。卷宗那一页留下的两句话（种子即身份证、
同种子同部署可逐 tick 复盘）原样带过去，一个字没改。

### 二、图鉴从五张表扩到十一张表

| 表 | 加的是什么 |
|---|---|
| 四本账 | 「三种资源」改四本——阅历这一行是新的，它只在重塑树里花 |
| 敌人志 | 护盾 / 每秒回血 / 死亡分裂落成一句话；**入场波数**从波次表现算，行序按波数排 |
| 波次与缩放 | 教学期入场、五波一轮主题、缩放曲线（挑 6 个波数现算） |
| 战况 | 九条加压项，每条带价格（+N%）与解锁条件 |
| 战备指令 | 十条，得与付并排写 |
| 结算口径 | 撤离 / 失守 / 深水 / 战况倍率 / 阅历逐项，数字全部从 `PAY` `EXP` 现读 |
| 重塑树 | 二十个节点一屏：花费、效果、前置 |
| 战绩 | 原卷宗那一张表 + 最近记录 + 去设置页的指路钮 |

**数字一律现算**这条老规矩在这里加倍重要：结算口径那一张表
直接读 `BS.metaDefs.PAY` 与 `EXP`，入场波数是扫 `waves.comp()` 扫出来的——
图鉴与实现之间没有第二份真相。改平衡从 world/ 的表改，这里跟着变。

### 三条值得记下来的

1. **数组里的界面串过不了覆盖门禁**。「四本账」那四行装在数组里喂给
   `T(rows[i][2])`，而覆盖门禁的抽取器只认 `T('字面量')`——它看不见数组。
   守那几行译文的是**逐页汉字扫描**（界面门禁）：英文模式把每页正文拼起来
   找 CJK。两条门禁守的是**两类不同的串**：字面量归覆盖检查管，
   拼出来 / 装起来的归页面扫描管。加第五本账时只跑 `npm test` 第一道
   是会漏的——这一版真的漏了一次（`阅历` 那一行），是扫描抓出来的。
2. **渲染前统一取词**。结算口径表最初五条里有一条是裸字符串、四条是
   `I.fill()` 好的，渲染时又只对标签过 `T()`——于是那条裸串在英文界面里
   露了汉字。对策写进代码注释：**每一行的值都在进数组之前取好词**，
   渲染时直接 `U.esc`。混着来就会漏，而漏的那一处恰好是最像数据的那一处。
3. **`.rrow` 的 grid 有 6 列、内容有 7 格**（种子那一格一直掉到第二行）。
   搬表的时候顺手修成 7 列——这种「不报错、只是难看」的 latent bug，
   只有把一处内容搬到明处再看一眼时才被发现。
