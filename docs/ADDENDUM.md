## 0. 诊断：它现在是十三个单向管道

把每个系统摊开，只问两个问题：**它读什么**、**它唯一影响的地方在哪**。

| 系统 | 输入 | 它影响的 | 有没有回来的路 |
|---|---|---|---|
| 图形工坊（1） | 手里的元件 | 塔的六项读数 | 无——塔在战场打成什么样，不会改回那具图形 |
| 库（2）/ 商店（3） | 采集尘、结晶 | 元件池、全局旋钮 | 无 |
| 花园（4） | 元件（种下去） | 五个 buff（`garden.buffs()`） | 无——战果不回花园 |
| 塔防（5） | 属性块 + flux + buffs | 一个波数 | 只有波数变成尘/晶回去 |
| 装配台（11） | 一座塔 + 40 结晶 | 这一座这一次出征 | 无 |
| 指针宇宙（99） | 存量（外源 `exogen()`） | 一个 `flux` 块 | 无——战场发生什么，网不知道 |
| 测量（7）/ 图鉴（9）/ 卷宗（8）/ 成就（6） | 同一批数据的只读投影 | 无 | 无 |

每一次改动都在这一张表里加一行，每一行都朝一个方向。**没有任何一处 A 读 B 的结果、B 又反过来改 A。**

后果不是「玩法少」，而是：**玩法总量 = 十三页之和，而不是十三页之积。**
玩家把每一页各读一遍，就等于把整个游戏读完了——第二遍不会再出现新东西。这就是「素」。

而你列出来的那些作品，全部是**积**：

| 作品 | 你做的唯一一件小事 | 长出来的 |
|---|---|---|
| GROW | 决定顺序 | 八种结局，没有一个写在按钮上 |
| 激突要塞 | 摆结构与朝向 | 两套系统的碰撞结果无法预演 |
| Bubble Tanks | 移动、射击、吸收 | 体积改变能力，能力改变可去的地方 |
| BioCage 1 | 决定吃什么 | 全场生物互相演化（正因为这个你嫌二代不好） |
| AU2 | 按常识行动 | 双窗里的另一块区域 |

**它们共同点不是「系统复杂」，是「上一层的输出是下一层的输入」。**

两处**与你的信条直接打架**，值得单独点出来：

### 1.1 塔的升级是纯量变

```js
// core/td.js:554
function levelMul(lv) { return 1 + LV_STEP * Math.pow(Math.max(0, lv | 0), BS.eff.POW); }
// LV_STEP = 0.25，0..9 级 —— 九次「更痛」，形状一次都没变过。
```

你写下的那句「**没有绝对的量变，只有绝对的质变**」，在这座塔上恰好是反的。
`docs/DESIGN.md §2.3` 花了很长篇幅解释「曲线要走 <1 的幂次，否则玩家只会全都升」——
那是在给一个**只有量变**的系统做止痛。真正让「先升哪一条」成为决策的不是凹函数，是**升到某一级时它变成另一个东西**。

### 1.2 有一个空槽一直在等

`spec.hp`（`world/towers.js:21`）→ `E.eff('towerHp', …)` 封在 400（`core/eff.js:17`）→ 一路传进 `td.addTower` 的 `t.hp`（`core/td.js:517`）→**然后一次都没被读过。**

塔有生命、有封顶、有稀有度、有轮廓读数（`edge` 决定它有多厚），但它从不受伤。
这不是 bug，是一个**已经通好电却没接灯泡的插座**：敌人若真能咬塔，「结构会崩」这件事才有物理。

### P1 阵型是一具图形 ★★★★★

**做法：** 本局摆下的那些塔，本身就是一具图形——把它们的格子拓成 `body`，
交给 `essence` 的**原套六项读数**（一格未改，与工坊、花园用的是同一把尺子）。

`essence` 现成、`body.stats` 现成、测量页的「目标切换」现成（`world/mods/measure.js:18` 的 `targets()` 再加一项 `field`）。
这是全案里唯一**几乎零成本**就能闭环的一处。

**它制造的新决策：** 摆位第一次不只是「覆盖范围」，还是「我在摆一具什么形状」。
而且落差是真的：

- 散着摆 → 点与点不相邻 → `环络 weave` 恒 0、`匀质 even` 低。
- 密排成一片 → 环络上来，那条接管 `chain` / `slow` 的流当场变响。

于是「摆得密一点还是摊开覆盖」从一个战斗问题，变成同时是**几何问题**。
这不是给他加一条加成，是让**已有的那条流**开始对玩家的摆法有反应。

**命中：** ⑦几何即内容、③涌现、⑧观察系统。

**落地：**

```js
/* core/run.js —— 阵型：本局摆下的格子拓成一具 body，交给 essence 原套算法。
   只读，不改任何判定。1×1 的点阵会读出一批极端的数——那本身就是信息：
   现在的阵型在几何上是十四颗孤立的点。 */
function formation(b) {
  if (!b) return null;
  var bd = BS.body.mk(), i, t;
  for (i = 0; i < b.towers.length; i++) {
    t = b.towers[i];
    bd.cells[t.cx + ',' + t.cy] = { e: 'f' + i, r: 0, ox: t.cx, oy: t.cy };
  }
  var st = BS.body.stats(bd, function () { return { w: 1, rar: 0, lv: 0 }; });
  return { n: st.n,
    es: { sym: st.esSym, repeat: st.esRepeat, void: st.esVoid,
          even: st.esEven, weave: st.esWeave, edge: st.esEdge },
    esScore: st.esScore || 0 };
}
```

第二刀（可选，改平衡）：把 `formation().esScore` 加进 `apex.exogen()` 的权重
（`core/apex.js:287` 那七项之和本来是 1.0，匀出 0.06 给它）——
那一刻「你的摆法」第一次真的进了那张网。

**门禁：** 同一批塔换一种摆法，六项读数必须变；密排的 `weave` 必须高于散摆；
换摆法不许改任何一塔的属性块（这条防的是「顺手把阵型读数乘进 dmg」）。

**风险：** 极低。它不参与判定。

### P2 质变口：2 / 5 / 10 级各开一口，一口一条，最多三口 ★★★★★

**做法：** 十级升级保留曲线，但 **2、5、10 三个口上不给伤害，给三选一**，
一口一条，最多三口（等级封顶同步抬到 10，否则第 10 级那一口根本到不了）。
选项**由这座塔自己的六项读数算出来**——同一具图形看不到同一张菜单，菜单本身是涌现出来的。
选中的东西是一条**规则**，不是乘区：

| 读数峰值 | 形变 | 规则改成 |
|---|---|---|
| 通透 void | **穿模** | 穿透不吃盾的五折——它就是为破盾而生的 |
| 对称 sym | **齐射** | 散射的每一发都打同一只，且每发按单体结算 |
| 环络 weave | **寄生** | 连锁在敌人之间留下引线，下一发沿引线走（连锁会「记住」） |
| 轮廓 edge | **殉爆** | 塔可以死：自毁造成范围伤害并返还一半辉光 |
| 重复 repeat | **过载** | 攻速 ×2，但每 10 秒停火 1 秒（它开始有节拍了） |
| 匀质 even | **沉压** | 同一只被连续命中时伤害递增（专治首领） |

**它制造的新决策：** 「这座塔往哪儿长」。
升到 10 级的路上有三个口，每一口都是「你这具图形允许它长成三种东西之一，而你只能挑一种」。
这正是 GROW 的机制搬到塔上：**同一批素材，不同顺序，不同结局。**

> **2026-10-18 修订（钉死这两条，别再改回去）：**
> ① 门在 **2 / 5 / 10**，由 `TD.GATE_LEVELS` 单点定义，界面与文档都从那里读；
> ② **一口一条**，`TD.MAX_MUT = 3`——同口叠加已废除（叠的是规则不是级数，
>   但三规则堆在一座塔上，玩家读不出「它长成了什么」，取舍也就没了）。
> 修它的探针：`_probe_gate.mjs`（node 跑，任一判据不成立即退出码 1）。

**命中：** ⑤演化、④结构、③涌现——**并且正面修掉 §1.1 那个矛盾**。

**落地：**

```js
// core/td.js —— 与 applyBranch 完全同形：纯函数、拷一份属性块、输入不动。
var MUTATIONS = [
  { id: 'phase', t: '穿模', need: 'void', ... },
  ...
];
function mutate(spec, id) { /* 返回新 spec，并写 spec.mut = id */ }
function optionsFor(spec) { /* 按 spec.es 排序取前三 —— 菜单本身是算出来的 */ }
// upgrade() 到口上不再加级，返回 { ok:true, need:'mutate', options:[…] }
```

存档记在 `rec.mut`（与 `rec.br` 同一个位置）；战场塔详情里出三选一。
`mut` 必须进 `spec` 的**深拷贝路径**——`td.removeTower` 的撤收会从 `armoryLog` 恢复，这一条别漏。

**门禁：** ①同一 spec 连过三个口，三次选项必须两两不同（否则菜单是常量）；
②选完之后**行为**必须变——断言 flags（`spec.mut === 'phase'` 时穿透打盾不掉五折），不是断言数值；
③不同图形的菜单必须不同（这条是「涌现」的硬判据，与「18 型两两不同」同一个写法）。

**代价：** 这是六条里唯一动平衡的。做完必须重跑 `_balance.mjs`，断崖位置会移。
**但这是全案最值一条**：它是「你的信条」与「你的游戏」之间唯一的正面回答。

**风险：** 中高。工程量约 2~3 天（含重标定）。

### P3 邻接回路：摆位从「覆盖」变成「接线」 ★★★★

**做法：** 现在相邻只有一条 `resona`（+10% 光环，`world/towers.js:41`）。
把它扩成**接缝**：相邻两座塔，按各自六读数算一个关系——

| 接缝 | 条件 | 效果 |
|---|---|---|
| **共振** | 两者峰值读数相同 | 共享该读数（两座都读到对方的峰值） |
| **串联** | 峰值互补（一个高一个低） | A 的击杀给 B 充能，B 下一发 ×1.5 |
| **干涉** | 峰值冲突且都高 | 两者伤害 −10%，但射程按两座之和算 |

**它制造的新决策：** 摆位从二维的「覆盖哪些格」变成一维的「谁挨着谁」。
一排塔的**排列顺序**第一次有意义——这是把塔防从「撒点」变成「布线」。

**命中：** ③涌现、⑦几何、④结构。

**落地：** `core/td.js` 的 `reaura()` 扩成 `rewire()`（纯函数，约 60 行）。
接缝类型记进 `b.wires`，渲染层拿它画线——**与 `beams` 同一套逻辑：判定是纯算法，线只是判定的可见面。**

**边界（容易破，先说死）：** `td.js` 不许 import `parts/tower/apex`。
接缝只能读 `spec` 上已经存在的数值（`spec.es` 是纯数据，读它不算越界），
门禁里那条「扫 td.js 的 BS.* 引用」照旧钉着。

**门禁：** 同两座塔换一个相对位置，接缝类型必须变；三座塔的排列顺序换一下，总输出必须变。

**风险：** 中。数值要重标一次。

### P4 无人值守：把一局托付出去 ★★★★

**做法：** 一个「托付」开关。三个可读的旋钮（不是隐藏权重）：

- **取向**：补塔 / 升级 / 平摊
- **门槛**：什么时候不打下一波（基地还剩几滴血就走）
- **摆法**：贴路 / 拉开 / 抱团

点了开始，你看它自己打完；结算时它把**自己做过的每一个决定**列成一张表
（第几波补了哪座、为什么、当时有多少辉光）。玩家第一次不是操作者，是**规则作者 + 观察者**。

**它制造的新决策：** 「我这条策略哪里不对」——这是唯一一种**不需要手速**的玩法，
也是最接近你列出的 神经鹅 / Screeps / 自动化 那一路的东西。

**它顺手解决一个工程问题：** `test/_balance.mjs` 现在手搓了一个装配器当探针，
那正是这个东西的雏形。**做一次，工具与玩法两用**——这个项目最爱的结构
（`tools/headless_check.mjs` 就是「验证工具顺手变成作品能力」的先例）。

**命中：** ⑧观察系统、⑨「原来还能这样玩」、④结构。

**落地：** `core/pilot.js`（新文件，约 120 行，**只调 `run` 的公开 API**——
不许它绕过任何闸门，否则它就成了一个作弊器）。战斗页一个开关 + 一份决定日志。

**门禁：** 同种子同策略 → 逐 tick 一致（它必须走同一条确定性路径）；
换一个旋钮 → 波数必须不同（**量不出差别时先问探针够不够强**，§9.2 的老教训）。

**风险：** 低。它不改任何判定。
副作用是好的：它会让平衡一眼被看穿。

### P5 双窗：最便宜的一颗种子 ★★★★

> AU2 里同时开两个浏览器窗口，会多出一块 Hot Coffee / Cold Coffee。
> 你说过那是一整份名单里影响你最深的一处。而这一部**一处都没有**。

**做法：** 存档在 `localStorage`（`core/bus.js:20` `KEY = 'templatd_v3'`），
两个标签页**天然共享同一份存档**。第二个窗口写档的那一刻，第一个窗口会收到 `storage` 事件：

```js
window.addEventListener('storage', function (e) {
  if (e.key !== BS.bus.KEY || !e.newValue) return;
  /* 有人和你开着同一份存档 —— 此刻起，这件事本身就是一条流。 */
});
```

一个「回声」：导航最下方多出一行不可点的读数（或第 25 条流、或花园多一圈苗床、
或指针宇宙的钟面上多一枚影子）。**它不该写进 README，不该有门禁，不该有成就。**
它该被某个人某天不小心发现。

**为什么它比任何一条机制都重要：** 它是唯一能制造「**游戏原来比我以为的更大**」这件事的东西，
而这个体验在你的十条轴里排第六、在你的人生里排第一。成本：20 行。

**门禁：** **不能有。** 有门禁的秘密就是说明书。
（代价要认：这类东西永远可能被下一个重构顺手删掉——所以代码里必须有一行注释写着「别删」。）

**风险：** 零（它不改任何判定，也不改存档结构）。

### P6 生态波：敌人之间互相吃 ★★☆

> BioCage 1 里你喜欢的是「所有生物大乱斗」，不是「进化」。这一部的敌人从来只跟塔打架，彼此不相干。

**做法：** 每 7 波一次「生态波」：灵体吃步行兵的残骸变大、重甲踩死冲刺兵、首领吃小怪回血。
玩家的目标从「杀光」变成「**打断这条食物链**」。

**命中：** ③涌现（而且是最纯的那种：状态之间互相影响）。

**风险：高。** 它会让难度曲线随机化（种子化能保住可复现，但断崖位置会漂），
与「第 8 波起带盾」那条精心标定的难度轴抢戏。**建议放进下一版，且只做「每 7 波」**——
把随机性关进笼子，像 `SHIELD_FROM = 8` 那样只响一次、可预期。

## 3. 我的排序（以及为什么砍掉一半）

```
第一批（不动平衡，只加「能看见的连接」）   P1 + P5      体感当场不同
第二批（不动判定，改玩法关系）             P4           玩家第一次能「看」
第三批（动判定，要重标平衡）               P2           正面修掉 §1.1
留到下一版                                 P3 / P6
```

理由只有一句：**先把管道接成网，再改网里的规则。**

现在的病不在「不深」——深的地方（指针宇宙的溯源、护盾的单体折价、花园的按件计量）
已经比大多数商业作品深。病在**每一处深都只深给自己看**：
十三页各说各话，所以玩家读完一页就再也没有理由回来。

P1 让「摆塔」这件事第一次有办法接进「那张网」（只读是一半，接上 `exogen` 才算通）；
P5 让「这个游戏」开始有一层不告诉你的事；
P4 让你从操作台前退后一步，第一次看见自己在设计的系统跑起来。
这三条加起来，才第一次有「一个东西在自己运转」的味道。

## 4. 明确不加的东西

这几条是**反向**的：它们会让游戏变大，但不会让它变深。

| 不加 | 为什么 |
|---|---|
| 剧情 / 世界观 / 角色文本 | 你列的作品里 GROW 一句台词都没有。规则优先于叙事，这是第一条轴 |
| 每日任务 / 签到 / 图鉴收集度 | 这是**内容包**：玩家的动作是「消费」，不是「发现」 |
| 再加敌人种类 / 塔的种类 | 5 敌 18 型已经够分工。再加是横着铺开——**更多内容 → 逐个消费**，正是你说不喜欢的那一边 |
| 教程 / 新手引导 | 「系统不向玩家让步」在你的清单里是加分项（变态人生大冒险）。引导会把这条抹掉 |
| 成就再加十条 | 九条已经覆盖全部事实。成就的价值在「它承认了一件我没说出口的事」，不在于数量 |
| 更多数值旋钮 | 17 条升级线里已经有 14 条是乘区。再加都是同一个东西的第 18 个版本 |

**判据（以后每条新提案都过这一关）：**
> 加完之后，玩家会不会**多做一件以前不能做的事**？
> 如果只是「同一个动作多了 10%」，那它属于上面那张表。

## 5. 一条提醒：这一部的门禁会替你验尸

`docs/DESIGN.md §9` 那三十几条翻车记录，绝大多数是**同一类错**：
「模型放开了，界面没放开」「量的时候探针选错了」「缓存与全局升级打架」。
P1~P5 每一条都会踩它们中的某几条，所以每条后面都写了门禁判据——
**不是为了绿，是为了在改完之后还能回答「它到底动了什么」。**

先做 P1 的话，最小验收是三条：
① 换摆法，六读数变；② 换摆法，塔的属性一个字节都不变；③ 测量页能选到「本局阵型」。
三条都过，它就真的只是「多了一个读数」——**然后你会在下一波自己发现「我想摆得密一点」**，
那一刻它就不是读数了。

## P1 阵型 —— 与提案一致，加了一条「双刃」

`run.js` 的 `formation()` / `formationFlux()` / `syncFlux()`。
六项读数各接管一组标量（匀质→伤害、重复→攻速、通透→射程+穿透、
对称→散射、环络→连锁+减速、轮廓→暴击），另有漏怪减免与辉光产出跟塔数走。

**提案里没有、实现时加上的一条**：峰值读数同时把敌血抬高一格（`hpMul`）。
理由：没有它，阵型乱流是一片纯正向的加成——难度墙会往后挪，而「摆法」
仍然只是个「怎么摆都更好」的问题，不构成决策。有了反噬，
「我这阵太偏环络了」才是一句有代价的话。**代价与收益写在同一个面板上。**

升级商店新增「阵型」组两条线接替「宇宙」组：阵型增益（读数幅度 +20%）与
峰值豁免（峰值反噬 −20%）。零级两个乘区都是 1，老存档手感逐字不变。

## P2 质变口 —— 两口，不是三口

提案写的是 3 / 6 / 9 三级，实做改成 **3 / 6 两级**。原因很硬：
六项读数 → 六种形变，一座塔一辈子各选一次（焊死）。**三口的话第三口必然空着**，
而空着的那口会静默退化成普通升级——那是这一部最讨厌的形状。
两口，六选二，诚实。

六种形变各自改**规则**而不是数字：
穿模（连锁不吃盾）· 齐射（散射锁同一目标）· 寄生（连锁不衰减）·
殉爆（塔可以死，换一圈范围伤害）· 过载（每发变两发，每 12 秒停火 2 秒）·
沉压（连续命中同一只逐发 +15%，最多 +60%）。

实现过程中改掉的两处：
- **过载原本写的是「攻速 ×2」**，量不出来——一个 tick 只有 0.5 秒，
  攻速超过 2 次/秒就表达不了，那条旋钮会静默失效。改成「每发变两发」。
- **沉压原本是无条件乘区**，结果每一座塔的第三发都莫名其妙变重。
  护盾那一节的精确断言当场红给你看——现在它只对长出沉压的塔生效。

## P3 邻接回路 —— 互补读全额，不是半额

`reaura()` 扩成 `rewire()`：相邻两座塔按各自读数峰值算一个接缝——
共振（同峰值、都不太响）互相抬一手；干涉（同峰值、都太响）伤害打折换射程；
互补（峰值不同、都够响）各读到对方整个峰值。

提案写的「半额」在实现时被 `Math.round` 吞成了 0（0.8 的一半是 0.4，
round 之后是 0）——那会让互补这条接缝**静默失效**。改成读全额，
并在注释里写清楚为什么不能写半额。
